# Migration Guide: ignite-element v2 (Ignite JSX & Renderer Strategies)

ignite-element v2 introduces the Ignite JSX runtime as the default renderer, renderer strategies, and an optional `ignite.config.ts` compatibility path for shared styles, diagnostics, and lit. This guide walks you through the upgrade from v1.x.

## TL;DR

1. **Update dependencies** – install the latest `ignite-element` and ensure your state-library peers (XState, Redux Toolkit, MobX) remain pinned.
2. **Configure TypeScript/JSX** – set `jsxImportSource` to `ignite-element/jsx` so JSX compiles against the Ignite runtime.
3. **Move styles into JSX** – use ordinary `<style>` tags or CSS text imported by your bundler for component-local styles.
4. **Use config only when needed** – keep `ignite.config.ts` for shared shadow-root styles, diagnostics, or opting into the lit strategy. `globalStyles` remains as a deprecated alias.
5. **Verify lifecycle** – shared adapters are reference-counted: they stop automatically when the last element disconnects (configurable if you prefer manual shutdown).

## 1. Upgrade ignite-element

```bash
pnpm add ignite-element@next
# or npm/yarn equivalent
```

Ignite JSX ships with no additional peer dependencies. If you still rely on lit templates, keep `lit-html` installed as before.

## 2. Configure TypeScript for Ignite JSX

Set the JSX runtime for your project. You can use a file-level pragma (`/** @jsxImportSource ignite-element/jsx */`) or configure it globally:

```jsonc
// tsconfig.json
{
  "compilerOptions": {
    "jsx": "react-jsx",
    "jsxImportSource": "ignite-element/jsx"
  }
}
```

This enables TypeScript (and most bundlers) to compile JSX using the Ignite runtime helpers (`jsx`, `jsxs`, `jsxDEV`).

## 3. Move component styles into JSX

The default path does not require `ignite.config.ts` or a bundler plugin. Keep component CSS next to the JSX that uses it:

```tsx
const toggleStyles = `
  :host { display: inline-block; }
  button { min-width: 5rem; }
`;

component("toggle-button", ({ isOn, toggle }) => (
  <>
    <style>{toggleStyles}</style>
    <button onClick={toggle}>{isOn ? "On" : "Off"}</button>
  </>
));
```

If the host enforces strict `style-src` CSP rules, prefer emitted stylesheet URLs through shared styles instead of inline `<style>` tags.

## 4. Optional config for shared defaults

Use config when you need shared stylesheet injection, diagnostics, or lit compatibility:

```ts
// ignite.config.ts
import { defineIgniteConfig } from "ignite-renderer";

export default defineIgniteConfig({
  styles: new URL("./styles.css", import.meta.url).href, // formerly globalStyles
  logging: "warn", // optional: "off" | "warn" | "debug"
  // renderer: "lit",
  // strategy: "replace",
});
```

Import this once in your app entry point when you need the advanced compatibility path. Legacy Vite/Webpack config auto-loading is no longer part of the stable `ignite-element` public API.

## 5. Update Renderers

- **Ignite JSX (default)** – author JSX directly in `component(tag, renderer)` calls. The facade callbacks (`states`, `commands`) remain unchanged.
- **lit strategy (optional)** – keep existing lit templates by setting `renderer: "lit"` in `ignite.config.ts` and importing `ignite-renderer/lit` near your config or app entry.

Example JSX component:

```tsx
/** @jsxImportSource ignite-element/jsx */

const component = igniteCore({
  source: toggleMachine,
  states: (snapshot) => ({ isOn: snapshot.matches("on") }),
  commands: ({ actor }) => ({ toggle: () => actor.send({ type: "TOGGLE" }) }),
});

component("toggle-button", ({ isOn, toggle }) => (
  <button onClick={toggle}>{isOn ? "On" : "Off"}</button>
));
```

## 6. Styling

Component-local `<style>` tags are the default Ignite JSX styling path. Shared styles can still flow through `defineIgniteConfig` when every component shadow root should receive the same stylesheet.

## 7. Shared Adapter Teardown

- Isolated adapters are stopped automatically on disconnect (unchanged).
- Shared adapters (long-lived instances you provide) are now reference-counted. Ignite releases the shared adapter once the final element using it disconnects. If you need full manual control over shared adapter teardown, pass `cleanup: false` to `igniteCore`/`createComponentFactory`.

```ts
const actor = createActor(machine);
actor.start();

const shared = igniteCore({ source: actor, states: /* ... */ });
shared("shared-counter", Renderer);

// Optional escape hatch: manage shared adapter teardown manually
const manual = igniteCore({
  source: actor,
  cleanup: false,
  states: /* ... */
});

manual("manual-counter", Renderer);

// Later, when the host app shuts down
actor.stop();
```

## 8. Additional Tips

- Type inference requires no extra helpers: inline your `states`/`commands` callbacks or reuse types from your state library (`InferStateAndEvent`, XState machine types, etc.).
- Keep renderer overrides in the advanced `ignite-renderer` layer rather than the stable `ignite-element` authoring path.
- Watch the changelog for follow-up improvements (lit strategy enhancements, devtooling).
