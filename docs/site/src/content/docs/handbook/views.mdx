The renderer turns source-derived values into a view. Use `ctx` to access those
values and source-directed commands without duplicating state in the view.

## Ignite JSX

Call `core('my-component', ctx => ...)`, as in the
[complete toggle](/ignite-element/#build-a-component). JSX files use `.tsx` and
`jsxImportSource: "ignite-element/jsx"`. No plugin or `ignite.config.ts` is required.
A source-free layout can use `igniteCore()` from `ignite-element`; it returns
only a registrar, without the source-backed runtime methods.

## React

Install `react` and `react-dom` for a web application. Use React's JSX runtime in
React files and the Ignite pragma in files that register Ignite JSX components.
Create the shared core outside rendering, then call `const ctx = useIgnite(core)`.

separate explicit headless runtime are described in
[ownership](/ignite-element/handbook/ownership/).

## Browser custom-element interoperability

When React intentionally hosts a real element, use
`igniteReact(handle)` from `ignite-element/react/web`. Its callback props receive
flat event detail and its typed ref calls commands on that element. See the
[separate interoperability demo](https://github.com/0xjcf/ignite-element/blob/beta/examples/frameworks/react/src/WebInterop.tsx).
Refs serve that recipe; ordinary shared-core views use `ctx`.

Plain HTML, Vue, and Svelte can use the registered tag, attributes, native DOM
events, and element commands. These browser capabilities do not imply a new
Ignite Vue/Solid hook. See the [framework examples](/ignite-element/handbook/examples/).

## Styling

Use native CSS inside the shadow root. In a renderer fragment:

Return a `<style>` element containing this CSS alongside the view:

```css title="Component CSS (fragment)"
:host {
  display: block;
  color: var(--counter-color, currentColor);
}
button {
  font: inherit;
  padding: 0.5rem 1rem;
}
```

Global selectors do not pierce shadow roots; inherited custom properties support
theming. Account for your application's CSP when using inline styles.
Use native controls, labels, and keyboard behavior; see
[accessibility](/ignite-element/guides/accessibility-first/).

The optional [Lit renderer and advanced configuration](/ignite-element/api/advanced-config/)
require their declared dependencies. Retained Canvas, WebGL, editor, map, and
native view resources belong to presentation lifecycle facilities. Ignite effects
are [notifications](/ignite-element/handbook/events/), not resource or commit hooks.
