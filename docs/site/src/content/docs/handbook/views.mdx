## Ignite JSX

Call `core('my-component', ctx => ...)`, as in the [light switch](/ignite-element/#build-a-component).

JSX files use `.tsx` and `jsxImportSource: "ignite-element/jsx"`.

A source-free layout can use `igniteCore()` from `ignite-element`; it returns only a registrar, without the source-backed runtime methods.

JSX `innerHTML`, `outerHTML`, `innerText`, `outerText`, `textContent`, `srcdoc`, and `dangerouslySetInnerHTML` are unsupported on intrinsic elements and are not applied. A `text` prop is not applied on `script`. A function component may still receive those prop names. `safeUrl`, `safeSpread`, and `trustedStyle` are exported from `@ignite-element/renderer/jsx`. `safeUrl` allows `http`, `https`, `mailto`, `tel`, and scheme-less strings, and refuses `//host`, `\\host`, and `/\host`. The renderer uses that allowlist for URL attributes. A `script` with `src`, and a `link` whose `rel` or `relList` is `stylesheet`, `preload`, `modulepreload`, or `import`, are not created. `prefetch`, `dns-prefetch`, `preconnect`, `prerender`, and `icon` links keep an `https` href. `host`, `hostname`, and the other URL property setters are not assigned. An `http` or `https` `iframe`, `frame`, or `embed` `src`, and an `object` `data`, are not applied. `data:` is refused except a raster image on `img` or `source`. `safeSpread` copies data props, drops real event handlers unless `handlers` lists that exact key, and drops `text`, `innerHTML`, and the other source-bearing keys. `trustedStyle(css)` is the only way to keep `url(`, `@import`, `expression(`, or a CSS backslash in style. It is a legal JSX child: `<style>{trustedStyle(css)}</style>`. The brand is a realm-wide symbol, so JSON cannot forge it and same-realm code can. A host [`mount`](/ignite-element/handbook/hosts/) may still assign `innerHTML`. That imperative callback is the escape hatch for trusted markup. `href`, `src`, `action`, `formaction`, and `xlink:href` accept only the `safeUrl` allowlist. Use JSX children for text. Trusted rich content belongs to a [host](/ignite-element/handbook/hosts/), which owns that element's subtree.

Passed `checked`, `value`, and `selected` are applied on every render, including an explicit `false`. `defaultChecked`, `defaultValue`, and `defaultSelected` run before those live props. Composition is the exception: after `compositionstart`, `value` is not written on a connected, focused input or textarea, so an `onInput` re-render does not reset the in-progress composition. `compositionend`, `blur`, a new `focus`, or disconnecting the element ends that suppression. The next render after any of them writes that `value`. Dropping `checked`, `value`, or `selected` leaves the live form state as it was. Development builds warn, for example `` `checked` dropped on a controlled input; pass it every render or use a catalog form component ``. The catalog will own form state through cores later. Passing two spellings of one prop (`acceptCharset` and `accept-charset`, `onClick` and `onclick`, `htmlFor` and `for`, `aria-label` and `ariaLabel`, `className` and `class`) is an authoring error. TypeScript rejects those pairs on JSX tags and in `jsx()` calls. Development builds warn otherwise. Production behavior for those attribute spellings is unspecified. URL and `on*` guards still apply to every spelling. Event spellings still bind one listener, and the last spelling wins. `scrollTop` and `scrollLeft` become `0`. Boolean props become `false`. A reflected attribute is removed. `htmlFor`, `HtmlFor`, `acceptCharset`, `AcceptCharset`, `className`, and `httpEquiv` remove `for`, `accept-charset`, `class`, and `http-equiv`. An ARIA IDL name such as `ariaLabel` removes `aria-label`. Dropping `defaultValue`, `defaultChecked`, or `defaultSelected` on a native element leaves that default as it was. `defaultChecked={false}` and `defaultSelected={false}` are sets. A native attribute or event key that is still present under another casing is not a drop. If the previous render set both spellings of one event and the next keeps one, the other listener is unbound. Every other native prop is left as it was, and dropping it writes no attribute. A present `false` on an own custom setter is assigned `false`, including on the first mount. When that prop is dropped, the setter is called with `undefined` only when it holds a previously set non-nullish value from the renderer, including a setter named `defaultValue`, `defaultChecked`, or `defaultSelected`. A prop that was never set, was only `null` or `undefined`, or was blocked is not called, and a later `null` or `undefined` after a drop is not called either. Own custom setters stay case-sensitive, so `foo` and `FOO` are different keys. `checked` and `CHECKED` are different sinks. Within one render, drops of absent old props run first, then present props are set, so a setter or attribute written for a present spelling is never erased by the drop of a differently cased old one. `length`, `options`, and `selectedOptions` are never set or reset.

### Re-entrant renders

A ref callback, a host `select`, `mount` or `update` callback, or a custom-element property setter may call `render()` synchronously. The newest requested view wins, and the superseded render stops without writing. Overriding or proxying built-in DOM members on rendered elements (for example `isConnected`, `childNodes`, `matches` or `getRootNode`), returning a Proxy thenable from `mount`, rendering from a `console` override or from a `ctx.signal` abort listener, and running several bundled copies of the renderer on one root are unsupported. In those cases the renderer keeps its own state consistent and the next render corrects the DOM, but intermediate writes are not guaranteed, and an error thrown by that code (the override, Proxy trap or thenable) reaches the caller of `render()`. A `console.warn` or `console.debug` override that throws during a development warning or fallback diagnostic also reaches the caller. Error reporting is contained: a throwing `console.error`, or a throwing `handleError`/`onError`, during renderer or host error reporting is swallowed and the render continues. A render or mount started into a root while it is being detached or while its view is released on disconnect, for example from a `ref(null)`, is ignored. If detaching throws part-way, the error reaches the caller. A root still in its original parent stays attached and the next render mounts the view again; a root that was removed or moved elsewhere is dropped, and the next `attach()` creates a fresh one.

This is the [runnable React example](https://github.com/0xjcf/ignite-element/tree/beta/examples/frameworks/react).

`useIgnite(core)` automatically unsubscribes when the component unmounts.

No cleanup `useEffect` is needed in the view.

The core stays available for other views and later mounts.

Call `core.dispose()` when you permanently discard that core, such as when its owning feature or session ends.

If you supplied an external actor, its owner stops it when nothing else needs it.

This example passes an existing actor, so the core is ready for `useIgnite(core)` without a preparation read.

## Styling

Use native CSS inside the shadow root.

Return a `<style>` element containing this CSS alongside the view:

```css title="Component CSS (fragment)"
:host {
  display: block;
  color: var(--counter-color, currentColor);
}
button {
  font: inherit;
  padding: 0.5rem 1rem;
}
```

Global selectors do not pierce shadow roots; inherited custom properties support theming.

Account for your application's CSP when using inline styles.

Use native controls, labels, and keyboard behavior; see [accessibility](/ignite-element/guides/accessibility-first/).
