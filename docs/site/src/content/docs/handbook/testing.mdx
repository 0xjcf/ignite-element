Test behavior at its owner boundary: the source, the core, then the rendered
controls. Use ordinary assertions. The [retired testing API](/ignite-element/api/testing-dsl/)
is migration material, not a prerequisite.

## Setup

For a browser-like Vitest host:

```sh title="Terminal"
pnpm add -D vitest jsdom @testing-library/dom
```

```ts title="vitest.config.ts"
import { defineConfig } from 'vitest/config';

export default defineConfig({
  test: { environment: 'jsdom' },
});
```

Use the same JSX settings as the application. No setup file or Lit dependency is
needed for the Ignite JSX example. Applications choosing Lit should declare
`@ignite-element/renderer` and `lit-html` directly and load that renderer in their
own test setup file.

## Cleanup and lifetime

Register each custom-element name once. Use fresh fixture-owned sources or
explicitly shared fixtures; do not dispose a core that later tests reuse.
Remove hosts, unsubscribe temporary observers, and terminally dispose test-owned
cores. Registered-core disposal is supported since beta.13. Stop borrowed sources
only when the test owns them. Use `try/finally` around the entire acquisition/use
boundary so failed assertions still clean up.

Test real disconnect/reconnect and same-tick moves when your behavior depends on
them. Do not infer lifecycle history or durable business receipts from a runtime
result. See [ownership](/ignite-element/handbook/ownership/) and the
[example index](/ignite-element/handbook/examples/) for broader fixtures.
