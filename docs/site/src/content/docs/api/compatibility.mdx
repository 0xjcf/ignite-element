Ignite Element v3 supports the versions below.

Install the state library your source entrypoint uses.

Install `lit-html` only when using the Lit renderer.

These are optional peer dependencies.

Your package manager warns if an installed version is below the minimum.

All four v3 packages are native ESM-only: `ignite-element`, `@ignite-element/core`, `@ignite-element/adapters`, and `@ignite-element/renderer`.

Their public ESM entrypoints and declarations are supported; CommonJS `main` and `require` entrypoints are not.

| Dependency | Required | Needed for |
| --- | --- | --- |
| Node.js | `>=22` | running the build/dev toolchain |
| TypeScript | `5.x` (authored against 5.9) | the typed JSX authoring path |
| `xstate` | `>=5.19.0` | `ignite-element/xstate` |
| `@reduxjs/toolkit` | `>=2.3.0` | `ignite-element/redux` |
| `redux` | `>=5.0.1` | `ignite-element/redux` (peer of Redux Toolkit) |
| `mobx` | `>=6.13.5` | `ignite-element/mobx` |
| `lit-html` | `>=3.2.1` | the optional legacy `lit` renderer |

The library version ranges come from each package's `peerDependencies`.

The Node and TypeScript rows describe the build and test toolchain.

:::caution[v3 is in beta]
v3 publishes under the `beta` dist-tag (the stable `latest` tag is still v2.2.x).

Pin a known-good range in your own `package.json` until the stable release.

See the [v2 → v3 migration guide](/ignite-element/migration/v3/).
:::

## Node runtime versus declaration support

The headless path is validated on Node 22.16.0, pnpm 10.33.0 and TypeScript 5.9.3.

Native `EventTarget`, `Event` and `CustomEvent` provide the runtime event path; Ignite does not fabricate browser globals.

Source-backed construction and execution need no DOM.

Tag registration is synchronous and requires a browser.

Other engines, workers and SSR/hydration are not established by this evidence.

Root/JSX optional-peer isolation, adapter inference with the selected peer, and compilation without `lib: DOM` are independent checks.

The package separates the neutral source entrypoints and `ignite-element/react` from browser declarations.

Genuine registration/JSX and the explicit `/react/web` consumers retain actual DOM types.

Do not install ambient browser stubs to make a native lane pass.

### TypeScript module resolution

The repository and strict packed-consumer profiles use TypeScript's `Bundler` module resolution.

A separate NodeNext probe still reports extensionless declaration-import resolution failures; NodeNext support is not established or claimed by Bundler success.

Native ESM runtime imports and strict no-DOM declaration consumption are distinct from that compiler-mode limitation.

### Owning-core lifetime

Source-backed owning cores expose terminal `dispose()` before and after successful custom-element registration.

It releases all Ignite observations and stops only a private Ignite-created XState actor; borrowed sources remain application-owned.

Disposed registered cores leave later connections inert.

Handles and projection sessions remain independently releasable.

With an existing actor, store or observable, the core is ready at construction and needs no preparation read before `useIgnite(core)`.

Machine, slice and fresh-factory inputs also work directly with `useIgnite(core)`, with a private runtime per hook and no preparation read.

Explicit headless access uses a [separate runtime](/ignite-element/handbook/ownership/#isolated-headless-cores).

Web Activity behavior was verified with React DOM 19.2.7.

Native host checks use React 19.1.0 and React Native 0.81.5; they do not establish native Activity or device acceptance.

Independent runtime retention uses `useInsertionEffect` internally for bookkeeping, beyond React's recommended CSS-in-JS use. Source activation and teardown occur outside that effect.

React DOM and the React Native test renderer have different commit ordering; passing the native Jest host does not establish every custom renderer's lifecycle behavior.

The hook never disposes its owning core on unmount.

SSR, framework commit barriers and native device execution are not implied.

See [Ownership & cleanup](/ignite-element/handbook/ownership/).
