The current `ignite-element@beta` v3 candidate supports the versions below. The state libraries and `lit-html` are **optional** peer dependencies — install only the ones the adapter you import needs. npm/pnpm warn if an installed version is below the minimum.

All four v3 packages are native ESM-only: `ignite-element`, `@ignite-element/core`, `@ignite-element/adapters`, and `@ignite-element/renderer`. Their public ESM entrypoints and declarations are supported; CommonJS `main` and `require` entrypoints are not.

| Dependency | Required | Needed for |
| --- | --- | --- |
| Node.js | `>=22` | running the build/dev toolchain |
| TypeScript | `5.x` (authored against 5.9) | the typed JSX authoring path |
| `xstate` | `>=5.19.0` | `ignite-element/xstate` |
| `@reduxjs/toolkit` | `>=2.3.0` | `ignite-element/redux` |
| `redux` | `>=5.0.1` | `ignite-element/redux` (peer of Redux Toolkit) |
| `mobx` | `>=6.13.5` | `ignite-element/mobx` |
| `lit-html` | `>=3.2.1` | the optional legacy `lit` renderer |

The version ranges come from each package's `peerDependencies`; the Node and TypeScript rows reflect the toolchain the v3 types and packages are built and tested against.

:::caution[v3 is in beta]
v3 publishes under the `beta` dist-tag (the stable `latest` tag is still v2.2.x). Pin a known-good range in your own `package.json` until the stable release. See the [v2 → v3 migration guide](/ignite-element/migration/v3/).
:::

## Node runtime versus declaration support

The headless-isolation development candidate is validated on Node 22.16.0, pnpm 10.33.0 and TypeScript 5.9.3. Native `EventTarget`, `Event` and `CustomEvent` provide the runtime event path; Ignite does not fabricate browser globals. Source-backed construction and execution need no DOM. Tag registration is synchronous and requires a browser. Other engines, workers and SSR/hydration are not established by this evidence.

Root/JSX optional-peer isolation, adapter inference with the selected peer, and compilation without `lib: DOM` are independent checks. Current root/adapter declaration graphs reference `HTMLElement`, `ShadowRoot` and other browser types: include the DOM library for those TypeScript consumers, without installing a runtime DOM shim. Full no-DOM declaration support and the stable support policy remain separate follow-ups. Documentation direct-topology examples use Actor-Web 0.2.1; adapter validation deliberately retains 0.2.0.

### Whole-core lifetime remains an open stable-readiness decision

Individual watcher/event handles and projection sessions release their observations. They do not signal that an entire core has been abandoned. Cached effects over application-owned live sources may retain subscriptions, and factory-owned actors may continue source work after the final individual watcher ends. Existing whole-core semantics are preserved: no automatic source shutdown, per-command reset, or new public disposal API is introduced. Application/source owners retain asynchronous work, cancellation and native shutdown. Completing DOM isolation does not close this resource-ownership decision.
