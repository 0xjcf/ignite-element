> Unreleased command-context change: These examples use `commands({ source })`, which is not available in beta.14. Use this candidate checkout until a supporting beta is published.

Use an adapter entrypoint's `igniteCore(...)` for source-backed construction.
The root source-free `const core = igniteCore()` remains registrar-only.
The canonical flow is source → native snapshot → derived states → renderer view.

This reference describes published beta.14 behavior. Beta.13 introduced automatic
shared-source readiness and terminal registered-core disposal, covered in the
[migration note](/ignite-element/migration/shared-readiness-terminal-disposal/).
Beta.14 adds [native DOM forwarding and core-owned effects](/ignite-element/handbook/events/).
No method or source input is added.

```ts
import { igniteCore } from 'ignite-element/xstate';

const counter = igniteCore({
  source: counterMachine,
  states: (snapshot) => ({ isOn: snapshot.matches('on') }),
  commands: ({ source: actor }) => ({ toggle: () => actor.send({ type: 'TOGGLE' }) }),
  events: (event) => ({ toggled: event<{ isOn: boolean }>() }),
  effects: ({ emit, select }) => {
    const isOn = select((snapshot) => snapshot.matches('on'));
    if (isOn.changed) emit({ type: 'toggled', isOn: isOn.current });
  },
});
try {
  const subscription = counter.watch((next, previous) => {
    console.log(previous.isOn, '->', next.isOn);
  });
  const result = await counter.execute({ command: 'toggle' });
  console.log(result.snapshot, result.states, result.events);
  console.log(counter.get('states'));
  subscription.unsubscribe();
} finally {
  counter.dispose();
}
```

Tag-and-renderer registration requires DOM; imports and headless construction do
not create browser globals or hidden elements. Existing opaque non-DOM projection
targets remain supported. A retained DOM element is not a projection target.

## Methods

### Keyed reads

`get(key)` accepts exactly `"states"`, `"schema"`, `"commands"`, and
`"events"`. There is no zero-argument form, raw-snapshot key, path language or
function lookup.

- `get("states")` reads the optional derived projection; omitted states return a
  stable empty object. Its first read prepares the owner runtime, real commands,
  and observation cache outside framework rendering.
- `get("schema")` returns the immutable minimal catalogue described below.
- `get("commands")` and `get("events")` select catalogue data, not functions or
  event history.

Native source APIs such as `actor.getSnapshot()` remain source-owned. Native
snapshots also remain in projections, effects and execution results. Separate
public reads are not an atomic multi-read transaction.

### `watch(handler)`

Observes derived states as `(next, previous)` with no initial user delivery.
Synchronous source replay seeds the previous value. Every delivered source
observation follows the adapter's existing notification/error boundary; Ignite
does not add global deep equality. The returned `{ unsubscribe() }` handle is
independently idempotent.

For an imperative initial render, subscribe first, then call `get('states')`, and
unsubscribe if that render throws. A first preparation read may return its
captured initial value while synchronous replay has already updated the framework
cache. See the complete [plain-controller observer](/ignite-element/guides/plain-controllers/)
for this pattern and source-owned asynchronous freshness guards.

### `on(name, handler)`

Observes flat outward occurrences `{ type, ...fields }`, including source-native
XState/Actor-Web emits. Source event names and payloads retain their inferred
types. This is not replay or history. Release its `{ unsubscribe() }` handle when
the observer ends.

### `execute({ command, input? })`

Calls one named command with exactly one positional argument, `input`, including
`undefined` when omitted. It never spreads an array. Strict types exclude
serialized calls requiring multiple positional arguments; direct callable
commands retain those signatures.

The promise awaits the callback and established queued-microtask observation
window. Its `{ snapshot, states, events }` result pairs native snapshot and
derived states from the same observation and includes ordered window events.
It does not promise business/network completion or independently correlated
receipts for overlapping calls. Wait for application-correlated source outcomes
when work continues asynchronously.

The result does not contain the command's resolved value. Direct `useIgnite(core)`
commands preserve that ordinary value/promise instead. Fulfillment can still mean
a guarded no-op or an unknown/rejected business outcome. Disposal invalidates an
outstanding execution observation, not its underlying I/O or an already-returned
direct command promise. The [plain-controller example](/ignite-element/guides/plain-controllers/)
demonstrates these distinctions with deterministic asynchronous ports.

An exact callback rejection remains the rejection even after disposal. A
callback that fulfills after disposal cannot acquire another result and rejects
with the disposed-result error. Already-returned direct command promises keep
their ordinary outcomes; Ignite does not cancel entered source work.

### `dispose()`

Source-backed owning cores release their own observation, event, effect,
projection, binding and command-window handles. They mark ended before cleanup,
prevent reentrant acquisition, attempt all releases in acquisition order, and
rethrow the first exact cleanup value, including `undefined` or `null`.
Repeated disposal is inert, even after a throwing first call. Individual handles
remain safe to release.

Live state reads, watches, listeners, commands and binding acquisition reject
after disposal. Catalogue reads remain available without reacquisition.

Since beta.13, final disposal also drains successfully registered views, making
later connections inert without unregistering or rebinding tag definitions.
Beta.12 rejects registered-core disposal **before teardown**. Failed registration
does not permanently lock the core, and registration-in-progress remains guarded.
Ordinary element disconnect/reconnect keeps its existing lifecycle.

## Source ownership

Borrowed XState actors, Redux stores, MobX values and Actor-Web sources remain
caller-owned. Disposal removes Ignite observations, never arbitrary source
shutdown. An Ignite-created private XState actor is stopped exactly once after
observations drain; an unused core never creates one.

A headless Actor-Web factory does not transfer native close authority, even if
it returns a new source. The application retains its handle and owns close.
The explicit `ignite-element/actor-web/web` host factory preserves existing
per-element factory-close behavior; asynchronous handle close is not awaited
backing-runtime shutdown. Web factories cannot be prepared headlessly.

## Discovery

Before binding a configured commands callback:

```json
{
  "schemaVersion": 1,
  "states": { "schema": null },
  "commands": null,
  "events": [{ "type": "toggled", "payload": null }]
}
```

After real binding, `commands` contains actual own names, for example
`{ "toggle": { "input": null } }`. With no commands callback, the known catalogue
is `{}` from the outset. Unknown is different from known empty.

The three null schema positions mean unknown runtime schemas, not no input,
validated input or unrestricted JSON Schema. Omitted states retain their known
empty-projection description. Catalogue reads acquire no source, run no commands
against fabricated actors, start no effects and initialize no DOM. Previously
returned objects never mutate. The latest catalogue survives disposal.

Declared event names are not an exhaustive list of native source emits. Observe
actual occurrences with `on` and execution results.

Explicit tool descriptions, input schemas and availability predicates belong at
the [tool/application boundary](/ignite-element/api/command-metadata/).
The core does not infer them. Project availability into public states while
preserving source enforcement; availability is not authorization.

## React and React Native

`useIgnite(core)` from `ignite-element/react` borrows a core created by its owner
outside rendering. Since beta.13, shared-source cores prepare at construction,
without the prerequisite `core.get("states")` read required in beta.12. Isolated headless
acquisition remains explicit. The hook returns inferred derived
states and stable callable commands. It uses pure cached reads and releases only
its own subscription on unmount. Snapshot values must be suitable immutable
projections: nested plain data is detached without freezing the source;
arbitrary class instances and accessors are not serialized. Function-valued
states remain states.

`igniteReact` and web-only wrapper types move to `ignite-element/react/web`;
they target actual registered elements, not a hidden headless runtime. No SSR
fallback or React commit barrier is provided. Since beta.14, effects use one
evaluator per core/source instance. Their queued execution is not a renderer or
framework commit barrier and may precede a view update. An activated shared
evaluator retains its baseline through zero-view intervals until `core.dispose()`;
isolated evaluators follow their instance lifetime. Effect errors use the core's
console fallback, not an element's error hook. See the [event guide](/ignite-element/handbook/events/)
for timing and migration; view resources belong to the actual framework lifecycle.

## Removed methods and private inspection

The former public `getSnapshot`, `watchSnapshot`, `getStates`, `watchStates`,
`getSchema`, and helper-dependent `canExecute` methods have no compatibility
aliases. The former testing/story/recording exports remain retired.

Document/speech projections retain a private coherent inspection for each
validation/commit attempt. It is not a public inspection bundle, and an external
asynchronous commit is not transactional with later source transitions.
