Every `igniteCore(...)` registration is also a **headless runtime**. The same value you call with a tag name to register a custom element exposes methods that drive and inspect the component contract without a DOM — the surface agents and tests use before any selector is involved.

```ts
import { igniteCore } from 'ignite-element/xstate';

const counter = igniteCore({
  source: counterMachine,
  view: ({ matches }) => ({
    isOn: matches('on'),
  }),
  commands: ({ actor }) => ({
    toggle: () => actor.send({ type: 'TOGGLE' }),
  }),
  events: (event) => ({
    toggled: event<{ isOn: boolean }>(),
  }),
  effects: ({ emit, select }) => {
    const isOn = select((snapshot) => snapshot.matches('on'));
    if (!isOn.changed) return;
    emit('toggled', { isOn: isOn.current });
  },
});

// Register a DOM projection later — the runtime is available immediately.
const { state, events } = await counter.execute('toggle');
const isToggleAvailable = counter.canExecute('toggle');
const current = counter.getSnapshot();
const view = counter.getView();
const schema = counter.getSchema();
```

## Methods

### `execute(commandName, payload?)`

Runs a command by name and resolves once the resulting transition settles. The payload type is inferred from the command function's first parameter, so commands that take no argument are called with the name alone.

**Returns** `Promise<{ state, events }>` — the state **after** the transition plus the ordered events emitted by that single transition (an `IgniteAgentExecutionResult`).

```ts
const result = await counter.execute('toggle');
```

The shape:

```ts
// IgniteAgentExecutionResult<State, Events>
{
  state: { value: 'on', context: {} },
  events: [{ type: 'toggled', payload: { isOn: true } }],
}
```

`events` is the same ordered stream the runtime emitted for that transition, so assertions stay deterministic and align with the events delivered to `on(...)` listeners.

For sources with a native emit stream (Actor-Web today), domain events the **source** emits during the command window are captured too — each as `{ type, payload }` where `payload` is the emitted event object — independent of the `events:` declaration. See [declared vs source-emitted events](/ignite-element/guides/actor-web/#emitted-events).

### `canExecute(commandName)`

Returns whether a command is available for the current snapshot. Commands without
a `canExecute` predicate are available by default; commands with
[`command(..., { canExecute })`](/ignite-element/api/command-metadata/#availability-predicates)
evaluate that predicate on demand.

**Returns** `boolean`.

```ts
const canToggle = counter.canExecute('toggle');
```

Unknown command names throw the same unknown-command error shape as
`execute(...)`.

### `getSnapshot()`

Returns the current raw snapshot of the underlying source.

**Returns** `State` — the underlying source snapshot (the XState snapshot, the Redux state, or the MobX observable value).

```ts
const snapshot = counter.getSnapshot();
```

The pre-stable `getState()` alias was removed at v3.0.0 — use `getSnapshot()`.

### `getView()`

Returns the current projected view — the object your `view(...)` builder derives from the snapshot.

**Returns** `View` — the projected view object, or `{}` when no `view` is configured.

```ts
const view = counter.getView();
```

### `on(eventName, handler)`

Subscribes to a public emitted event. The handler receives a `CustomEvent` whose `detail` is the event payload.

**Returns** a subscription — `{ unsubscribe(): void }`. Call `unsubscribe()` to stop listening.

```ts
const subscription = counter.on('toggled', (event) => {
  console.log(event.detail.isOn);
});

subscription.unsubscribe();
```

Use `on(...)` for the public events your component emits through `effects`. When the source has a native emit stream (Actor-Web today), `on(...)` also receives the source's emitted domain events — `event.detail` is the emitted event object itself, and the names are typed from the source's `Emitted` union. (The pre-stable `subscribe(eventName, handler)` alias was removed at v3.0.0 — use `on`.)

### `watchSnapshot(handler)`

Subscribes to **raw snapshot** updates. The handler receives `(snapshot, prevSnapshot)` on every source update.

**Returns** a subscription — `{ unsubscribe(): void }`.

```ts
const subscription = counter.watchSnapshot((snapshot, prevSnapshot) => {
  console.log(prevSnapshot.value, '->', snapshot.value);
});
```

The pre-stable `watch(handler)` alias was removed at v3.0.0 — use `watchSnapshot()`.

### `watchView(handler)`

Subscribes to **projected view** updates. The handler receives `(view, prevView)` on every view change.

**Returns** a subscription — `{ unsubscribe(): void }`.

```ts
const subscription = counter.watchView((view, prevView) => {
  console.log(prevView.isOn, '->', view.isOn);
});
```

### `getSchema()`

Returns a JSON-serializable contract describing the component's commands, public events, and current state. Command metadata declared with [`command(...)`](/ignite-element/api/command-metadata/) is included here.

**Returns** `{ commands, events, state }` — a JSON-serializable `IgniteAgentSchema`: `commands` maps each name to its metadata (`{}` when none), `events` is the array of declared event names, and `state` is the current state value. Commands with an availability predicate include `gated: true`; call `canExecute(commandName)` for the current boolean result.

```ts
const schema = counter.getSchema();
```

The shape:

```ts
// getSchema() returns:
{
  commands: {
    toggle: {},
  },
  events: ['toggled'],
  state: { value: 'off', context: {} },
}
```

:::note[Dynamic events are not listed]
`events` enumerates only the names **declared** in the `events:` map. Events emitted by the source itself (the Actor-Web [emitted-event bridge](/ignite-element/guides/actor-web/#emitted-events)) are a compile-time union with no runtime registry, so they don't appear in the schema — observe them via `on(...)` and `execute().events` instead.
:::

### `record(name)`

Starts a named [story](/ignite-element/api/testing-dsl/#stories) recorder over the same runtime.

**Returns** a [story](/ignite-element/api/testing-dsl/#stories) — an object that records command, state, view, and event activity as one ordered behavior trace (`execute`, `until`, `trace`, `lifecycle`, `summary`, `stop`).

```ts
const story = counter.record('toggles on');
```

## Determinism

The runtime seeds `prevSnapshot` on attach, never replays history, and runs `effects(...)` once per update in a stable order — which is what keeps `execute()` and the testing helpers reproducible. The full semantics are documented once in [Deterministic effects](/ignite-element/concepts/the-ignite-model/#deterministic-effects).
