`igniteCore` adapts your state source (XState, Redux, MobX) into a render-ready component factory.

```ts
import { igniteCore } from 'ignite-element/xstate';

const component = igniteCore({
  source: machineOrActor,
  events: (event) => ({ /* typed events */ }),
  view: ({ context }) => ({ /* derived values */ }),
  commands: ({ actor, host }) => ({ /* actions */ }),
  effects: ({ snapshot, prevSnapshot, emit, actor, host, select }) => { /* consequences */ },
});

component('tag-name', (props) => /* JSX or lit template */);
```

## Parameters

- `source`: machine definition or started actor (XState), Redux store/slice, or MobX observable.
- `events(mapper)`: optional; defines typed DOM events.
- `view(ctx)`: derive render props from the snapshot context — an object snapshot's fields are spread onto `ctx` (with `ctx.snapshot` still available); runs on mount and on changes.
- `commands(context)`: expose actions; receives `{ actor, host }`.
- `effects(snapshot, prevSnapshot, context)`: optional; runs after every state update and receives `{ emit, actor, host, select }`.
- `cleanup`: defaults to `true`; shared adapter teardown override. When enabled, Ignite releases the shared adapter after the last element disconnects. Releasing the adapter stops Ignite-owned sources (e.g., XState machine actors); user-provided sources are never stopped.

## Returns

A **component factory** — call it as `component(tagName, renderer)` to register the custom element (returns nothing). The same value is also the [headless runtime](/ignite-element/api/headless-runtime/): it carries `execute`, `getState`, `getView`, `getSchema`, `on`, `watch`, `watchView`, and `record` for driving and inspecting the component without the DOM.

## Advanced overrides

`cleanup` controls shared adapter teardown; most components won't need to change it.

```ts
const component = igniteCore({
  source: actor,
  cleanup: false, // keep the shared adapter alive after the last element disconnects
});
```

See [The Ignite model](/ignite-element/concepts/the-ignite-model/) for adapter-specific behavior.

## Headless runtime

Every component registration also exposes a headless runtime (`execute`, `getState`, `getView`, `getSchema`, `on`, `watch`, `watchView`, `record`) for driving and inspecting behavior without the DOM. See [Headless runtime](/ignite-element/api/headless-runtime/) for the full method reference.
