`igniteCore` adapts your state source (XState, Redux, MobX, or Actor-Web) into a render-ready component factory. The data path stays explicit: source → native snapshot → derived states → renderer view.

```ts
import { igniteCore } from 'ignite-element/xstate';

const core = igniteCore({
  source: machineOrActor,
  events: (event) => ({ /* typed events */ }),
  states: (snapshot) => ({ /* derived values */ }),
  commands: ({ actor }) => ({ /* actions */ }),
  effects: ({ snapshot, prevSnapshot, emit, select }) => { /* outward facts */ },
});

const component = core('tag-name', (ctx) => /* JSX or lit template */);

component.tagName;
component.get('schema');
```

## Parameters

- `source`: machine definition or started actor (XState), Redux store/slice, or MobX observable.
- `events(mapper)`: optional; declares names and payload types, not emissions or runtime schemas. See [Events](/ignite-element/guides/events/) for unreleased native DOM forwarding and producer checks.
- `states(snapshot)`: optionally derive a plain object from the bare native snapshot; runs during preparation/rendering and source observations. Omission yields one stable empty object. Since beta.13, initial shared preparation occurs at construction.
- `commands(context)`: expose actions; receives `{ actor }`.
- `effects(context)`: optional; receives `{ snapshot, prevSnapshot, select, emit }` and stays synchronous. **Unreleased after beta.13:** one evaluator per core/source instance queues each delivered update after its initial baseline; consumers do not create separate runners. See [Events](/ignite-element/guides/events/) for activation, ownership and migration.
- `cleanup`: shared-adapter element-refcount teardown override, not native source ownership. Defaults to `false` for shared sources. Set `cleanup: true` to release the shared adapter after the last element and retained observation handle leave. An activated shared effect evaluator retains observation until terminal core disposal, even with this option. Owning-core disposal is separate: borrowed sources are never stopped, while a private Ignite-created XState actor is stopped exactly once. Headless Actor-Web factory invocation does not transfer close authority.

## Returns

A **component factory and headless runtime**. Call it as `core(tagName, renderer)` to register a custom element and receive a component handle. The handle exposes the registered `tagName` and delegates `get('schema')` to the same runtime:

```ts no-check
const component = core('counter-button', renderer);

component.tagName; // 'counter-button'
component.get('schema');
```

The source-backed callable `core` carries `get`, `watch`, `on`, `execute`, and `dispose`. Read keys are exactly `states`, `schema`, `commands`, and `events`; component handles expose only the appropriate discovery keys. In beta.12, successful registration prevents owning disposal. Since [beta.13](/ignite-element/migration/shared-readiness-terminal-disposal/), existing `dispose()` is terminal after registration; it adds no rebinding or source-ownership API. Root source-free construction returns only its registrar.

The accepted one-argument overload binds an opaque non-DOM projection target and returns a disposable projection session:

```ts no-check
const session = core(projectionTarget);
session.dispose();
```

Create supported targets with `createProjectionDocumentTarget(...)` or `createProjectionSpeechTarget(...)`; a retained DOM element is not a projection target.

## Advanced overrides

`cleanup` controls shared-adapter teardown; most components won't need to change it. A consumer-owned shared source is kept alive for the core's lifetime by default — pass `cleanup: true` only to opt a shared core back into element-refcount teardown of the adapter when no activated effect evaluator retains it.

```ts
const component = igniteCore({
  source: actor,
  cleanup: true, // opt this shared core back into element-refcount teardown of the adapter
});
```

See [The Ignite model](/ignite-element/concepts/the-ignite-model/) for adapter-specific behavior.

## Headless runtime

Source-backed construction exposes the runtime before registration. Tag-and-renderer registration requires a browser and otherwise throws a synchronous DOM-registration error without acquiring additional source observations. Renderer defaults are selected at registration, not construction; an explicit strategy bypasses default resolution. The registered tag retains its selection across rendering and reconnection. See [Headless runtime](/ignite-element/api/headless-runtime/) for the method reference and lifetime limitation.

## Callback boundaries

- Commands express explicit intent. Pass user or host-derived data as command input instead of reading it from an implicit host object.
- Effects stay synchronous and queue outward facts after source processing, without promising that every framework has committed its view. Core-owned errors use the console fallback, not a particular element's error hook. Move async environmental work, retries, cancellation, and feedback loops into source/application ports.
- DOM event dispatch and internal error routing still exist, but the host stays an internal runtime concern rather than a public callback capability.

```ts
effects: ({ snapshot, prevSnapshot, select, emit }) => {
  // Synchronous transition-to-outward-fact behavior.
  // No async environmental work.
};
```
