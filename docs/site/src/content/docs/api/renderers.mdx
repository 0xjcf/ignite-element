Ignite JSX is the default renderer and works without `ignite.config.ts`. Components can render JSX directly and keep component CSS in local `<style>` tags.

## Optional advanced renderer config

Use config only when you need project-wide strategy overrides or the legacy `lit` renderer:

```ts
import { defineIgniteConfig } from '@ignite-element/renderer';

export default defineIgniteConfig({
  renderer: 'lit',
  strategy: 'replace',
});
```

## Assets & styles

Component-level `<style>` tags are the default scoped styling path. Shared `styles` declared in config are injected into every component shadow root when you opt into that advanced config path.

## Advanced primitives

`@ignite-element/renderer` exposes a small set of advanced primitives for custom render strategies and config introspection. Ordinary v3 apps never need these — they are for tooling, custom renderers, and diagnostics.

```ts
import {
  registerRenderStrategy,
  resolveRenderStrategy,
  getRegisteredRenderStrategies,
  getIgniteConfig,
} from '@ignite-element/renderer';
```

- `registerRenderStrategy(rendererId, factory)` — register a custom render-strategy factory under a renderer id. The built-in `ignite-jsx` (default) and `lit` strategies register themselves when you import their entry points.
- `resolveRenderStrategy(rendererId)` — return the factory registered for an id, falling back to the default strategy (with a warning) if the id is unknown.
- `getRegisteredRenderStrategies()` — list the renderer ids that currently have a registered strategy.
- `getIgniteConfig()` — read the effective config resolved from [`defineIgniteConfig`](/ignite-element/api/define-ignite-config/); returns `undefined` when no config is registered.

Other symbols on the package (e.g. `injectStyles`, `flushPendingStyles`, `getGlobalStyles`/`setGlobalStyles`) are `@internal` implementation details. Manage shared styles through `defineIgniteConfig({ styles })` instead.

## Notes and troubleshooting

- `lit` is no longer part of the stable `ignite-element` public surface. Import `@ignite-element/renderer/lit` only when you intentionally opt into that advanced compatibility path.
- Legacy config-loader plugins are not part of the stable `ignite-element` v3 API. Keep them only in existing compatibility setups you already own.
- Missing config keeps the Ignite JSX default. Invalid configured renderer values are normalized by legacy compatibility behavior and logged; avoid relying on that path.
