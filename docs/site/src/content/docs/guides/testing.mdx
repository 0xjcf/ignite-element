Test the state source and the DOM separately. Keep your XState/Redux/MobX logic covered with its own unit tests, then add light DOM tests for the web components.

## Behavior tests vs. DOM tests

Use ordinary Vitest or Node assertions on the [headless runtime](/ignite-element/api/headless-runtime/), then mount real registered components for DOM tests. The flow remains `source → source-native snapshot → derived states → renderer view`. The former testing DSL, recording and accessibility bridge are retired; see the [migration notice](/ignite-element/api/testing-dsl/).

## Commands, events, and external updates

This Redux example preserves command-input, native-snapshot, derived-state, availability and event assertions. The store and the external operation belong to the test, not Ignite.

```ts
import { expect } from 'vitest';
import { configureStore, createSlice } from '@reduxjs/toolkit';
import { igniteCore as igniteRedux } from 'ignite-element/redux';

const counterSlice = createSlice({
  name: 'counter',
  initialState: { count: 0 },
  reducers: {
    add: (state, action: { payload: number }) => { state.count += action.payload; },
    decrement: (state) => { state.count -= 1; },
  },
});
const store = configureStore({ reducer: { counter: counterSlice.reducer } });
const recoveryCounter = igniteRedux({
  source: store,
  states: (snapshot) => ({
    count: snapshot.counter.count,
    canDecrement: snapshot.counter.count > 0,
  }),
  commands: ({ actor, command }) => ({
    increment: (amount: number) => actor.dispatch(counterSlice.actions.add(amount)),
    decrement: command(() => actor.dispatch(counterSlice.actions.decrement()), {
      canExecute: ({ snapshot }) => snapshot.counter.count > 0,
    }),
  }),
  events: (event) => ({ 'counter-incremented': event<{ count: number }>() }),
  effects: ({ snapshot, prevSnapshot, emit }) => {
    if (snapshot.counter.count !== prevSnapshot.counter.count) {
      emit({ type: 'counter-incremented', count: snapshot.counter.count });
    }
  },
});

expect(recoveryCounter.getSnapshot().counter.count).toBe(0);
expect(recoveryCounter.canExecute('decrement')).toBe(false);
const result = await recoveryCounter.execute({ command: 'increment', input: 2 });
const countedEvent: Awaited<ReturnType<typeof recoveryCounter.execute>>['events'][number] =
  { type: 'counter-incremented', count: 2 };
expect(result.snapshot.counter.count).toBe(2);
expect(result.states).toEqual({ count: 2, canDecrement: true });
expect(result.events).toEqual([countedEvent]);
expect(recoveryCounter.canExecute('decrement')).toBe(true);
const observed: number[] = [];
const subscription = recoveryCounter.watchStates((states) => observed.push(states.count));
try {
  store.dispatch(counterSlice.actions.add(1));
  expect(recoveryCounter.getSnapshot().counter.count).toBe(3);
  expect(recoveryCounter.getStates().count).toBe(3);
  expect(observed).toContain(3);
  await recoveryCounter.execute({ command: 'decrement' });
  expect(recoveryCounter.getSnapshot().counter.count).toBe(2);
} finally {
  subscription.unsubscribe();
}
```

`execute()` awaits its callback and defined observation, not every asynchronous business operation triggered by the source. Resolve fixture-owned ports and use bounded `vi.waitFor` assertions on correlated source snapshots/events for those outcomes. Keep cancellation and stale-result checks. Effects do not own that asynchronous work.

## Setup

- Use a browser-like runner (e.g., Vitest + JSDOM). If you rely on advanced `@ignite-element/renderer` config, shared styles, or the legacy `lit` renderer, import that setup once before tests.
- Register each custom-element name once. Remove mounted elements and settle observation cleanup after each test; unsubscribe test observers and stop sources owned by the test.
- Add `@testing-library/dom` as a development dependency to query actual rendered controls.

Tests that import the scoped lit renderer must declare it and its peer directly: `pnpm add -D @ignite-element/renderer@beta lit-html` (with `ignite-element@beta` in application dependencies). Normal facade/JSX tests do not need a direct scoped-package dependency.

```ts
import { defineConfig } from 'vitest/config';

// test/setup.ts
import './ignite.config'; // only if your app uses ignite.config.ts
import '@ignite-element/renderer/lit'; // only if your tests use the lit renderer

// vitest.config.ts
export default defineConfig({
  test: {
    globals: true,
    environment: 'jsdom',
    setupFiles: ['./test/setup.ts'],
  },
});
```

## State tests (XState example)

Write a machine test exactly as you would without Ignite.

```ts
// counter.machine.ts
import { assign, setup } from 'xstate';

export const counterMachine = setup({
  types: {} as {
    context: { count: number };
    events: { type: 'INC' } | { type: 'DEC' };
  },
}).createMachine({
  context: { count: 0 },
  on: {
    INC: { actions: assign(({ context }) => ({ count: context.count + 1 })) },
    DEC: { actions: assign(({ context }) => ({ count: context.count - 1 })) },
  },
});

// counter.machine.test.ts
import { createActor } from 'xstate';
import { describe, expect, it } from 'vitest';
import { counterMachine } from './counter.machine';

describe('counter machine', () => {
  it('increments and decrements', () => {
    const actor = createActor(counterMachine).start();

    try {
    actor.send({ type: 'INC' });
    expect(actor.getSnapshot().context.count).toBe(1);

    actor.send({ type: 'DEC' });
    expect(actor.getSnapshot().context.count).toBe(0);
    } finally { actor.stop(); }
  });
});
```

## DOM tests (web component + XState + Lit)

Register the component once, mount it, and drive it via the shadow DOM. The example below uses the Lit renderer and a fresh test-owned actor with increment/decrement behavior.

```ts
import { within } from '@testing-library/dom';
import { igniteCore } from 'ignite-element/xstate';
import '@ignite-element/renderer/lit';
import { html } from 'lit-html';
import { assign, createActor, createMachine } from 'xstate';
import { expect, it } from 'vitest';

it('renders accessible controls and responds to clicks', async () => {
  const source = createActor(createMachine({
    context: { count: 0 },
    on: {
      INC: { actions: assign(({ context }) => ({ count: context.count + 1 })) },
      DEC: { actions: assign(({ context }) => ({ count: context.count - 1 })) },
    },
  })).start();
  const core = igniteCore({
    source,
    states: (snapshot) => ({ count: snapshot.context.count }),
    commands: ({ actor }) => ({ inc: () => actor.send({ type: 'INC' }), dec: () => actor.send({ type: 'DEC' }) }),
  });
  const name = 'tested-counter-' + crypto.randomUUID();
  core(name, ({ count, inc, dec }) => html`
    <section>
      <output aria-label="Counter status">${count}</output>
      <button type="button" @click=${dec}>Decrement</button>
      <button type="button" @click=${inc}>Increment</button>
    </section>
  `);
  const host = document.createElement(name);
  document.body.appendChild(host);
  try {
    const section = host.shadowRoot?.querySelector('section');
    if (!section) throw new Error('Counter did not render');
    const controls = within(section);
    controls.getByRole('button', { name: 'Increment' }).click();
    await Promise.resolve();
    expect(controls.getByRole('status', { name: 'Counter status' }).textContent).toBe('1');
    controls.getByRole('button', { name: 'Decrement' }).click();
    await Promise.resolve();
    expect(controls.getByRole('status', { name: 'Counter status' }).textContent).toBe('0');
  } finally {
    host.remove();
    await new Promise<void>((resolve) => queueMicrotask(resolve));
    source.stop();
  }
});
```

## Observation and lifetime checks

Use named construction: a source-backed `const core = igniteCore({ source, ... })`, or `const core = igniteCore()` from the root for source-free presentation. Query real rendered elements; do not cast a shadow root or reconstruct the removed accessibility bridge.

Test disconnect, move and reconnect through actual elements. A held `watchStates` or `watchSnapshot` subscription may retain observation after the last element disconnects; release it explicitly. Ignite observation cleanup does not stop caller-owned actors or stores. Runtime results are not deep-cloned portable receipts and observations do not reconstruct complete internal lifecycle histories.
