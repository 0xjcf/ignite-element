Preserve an existing plain TypeScript controller: translate its snapshots,
subscriptions and guarded methods into a supported structural source. No XState
conversion, new adapter package or workflow rewrite is required.

## Run the complete example

The private, non-publishable project at
[`examples/apps/shared-controller`](https://github.com/0xjcf/ignite-element/tree/beta/examples/apps/shared-controller)
models only a **synthetic display-density preference**: `comfortable` or `compact`.

the complete files are already in the reviewed checkout. It makes no network calls.

From that checkout, with Node 22.16.0 and the repository's pinned pnpm 10.33.0:

```sh

pnpm --filter ignite-element... build
pnpm --dir examples/apps/shared-controller install --ignore-workspace --no-link-workspace-packages --frozen-lockfile
pnpm --dir examples/apps/shared-controller typecheck
pnpm --dir examples/apps/shared-controller test
pnpm --dir examples/apps/shared-controller dev
```

The example links the checked-out public package, whose exports resolve the built
candidate. Its Vite configuration deduplicates React for this linked checkout;
it does not alias private library source or alter the package exports. The root
example discovery and exact-coverage lanes include this example.

For isolated **packed** web, native and neutral consumers, build first, then run:

```sh
node examples/apps/shared-controller/scripts/packed-consumers.mjs
```

The script packs all four current packages, checks exact internal versions,
records tarball SHA-256 values, installs them through explicit file dependencies
and overrides, and verifies frozen installs. It retains a new external directory
with source copies, logs and locks; no workspace fallback or source aliases are
used there. The complete native component is strictly checked without the DOM
library and exercised through actual React Native test-host components.
This fixture is React 19.1.0 / RN 0.81.5, **not** arbitrary Expo or device support.
The neutral lane intentionally cannot resolve Actor-Web runtime, React DOM, Lit
or unrelated source ecosystems. React is a legitimate dependency of its hook.

These rendered code blocks import the canonical example files directly; the

## Keep behavior in the controller

The flow is **source → native snapshot → derived states → view**.
`controller.ts` owns loading, pending operations, guards, revisions, epoch-bound
receipt matching and recovery. `states.ts` derives portable presentation meaning
and permitted actions. `fake-ports.ts` supplies deferred transport results and a
manual clock: advance five simulated seconds to show uncertainty, then deliver a
matching acceptance to show late confirmation. A wait deadline is not cancellation.

The controller validates intents even when called headlessly or through an old
handler. It retains the last confirmed value while saving. An explicit rejection
allows retry; an unknown outcome does not authorize resubmission. A query may
observe a value but cannot prove completion of an unresolved write. Late reads
cannot replace newer write facts. These are example application rules, not
Ignite's policy or server authorization.

Directory labels are not API requirements. A capability's `source/` folder may
hold ports and contracts, while Ignite's `source:` supplies behavior observations.
Ignite's `states:` callback is a projection, not the controller's transitions.
Keep shared behavioral composition with the application capability; views may
format or map presentation data without reimplementing legality or success.

one source **value**, not a per-view factory that accidentally creates competing
workflows. A new login epoch gets a new owner, even for the same account.

Remove or replace views first, then dispose the old owner. Individual route
unmounts only unsubscribe: pending work belongs to the session. Cleanup attempts
both Ignite teardown and application-owned controller shutdown; preparation errors
remain visible even if cleanup also fails. This controller has no transport-abort

synchronize pending work between devices.

## Commands, observations and receipts

The full reference is [Headless runtime](/ignite-element/api/headless-runtime/):
`get("states" | "commands" | "events" | "schema")`, `watch`, `on`, `execute`,
and `dispose`. Root source-free `igniteCore()` is a registrar, not this runtime.
Removed snapshot/state getter aliases and command metadata helpers stay removed;
source-native APIs remain valid on the source itself.

- Discovery reads (`schema`, `commands`, `events`) do not acquire the source.
  Unknown schemas are `null`; command discovery may be unknown before real binding.
  Discovery is not a command-function lookup or runtime input validator.
- A direct hook command preserves its underlying return and promise. Here
  `choose` resolves `void` for accepted, guarded no-op, rejected and unknown
  outcomes. **Fulfillment is not a success announcement.** Every view reads the
  controller's shared outcome meaning instead.
- `execute({command, input})` passes one value, awaits the callback, and returns
  `{snapshot, states, events}`—not its resolved command value. A synchronous
  ecosystem `send()` does not itself await separately invoked network work.
- Overlapping execution windows can contain the same events. The accepted focused
  control establishes that limit; do not treat these arrays as independent causal
  receipts. Application/server operation identities and receipt validation remain
  necessary. This small controller's receipt fields do not create a generic
  persistence or retry protocol.
- Disposal is terminal and idempotent for an unregistered core. A pending
  `execute` cannot produce a new result after disposal, but already-returned
  direct command promises keep their ordinary outcome. Existing I/O may continue.

A successfully registered core rejects `dispose()` before teardown.
[`ignite-element/react/web`](/ignite-element/guides/host-app-integration/)
wraps actual registered elements; `ignite-element/actor-web/web` supplies a
DOM-host factory boundary. Neither is a generic external-core binding.

Effects are synchronous callbacks queued after Ignite's own renderer update.
They can precede a React commit and do not replace framework effects. Environmental
I/O and retained presentation resources stay in application ports and presentation
owners. Dedicated Solid/Vue bindings, SSR/hydration, SwiftUI/Compose and the
separately accepted but unimplemented retained `ref`/`commit`/keyed design are not
supplied by this example.
