The flow is __source → native snapshot → states → renderer view__.

Pass the same source instance to a core to share its state across views.

[Shared sources](/ignite-element/explainers/shared-sources/) walks that path on the Smart Home: one started actor, a panel, and a scripted command.

Each application process owns its instances.

Sharing code does not synchronize devices.

For observation and terminal disposal, see [Ownership & cleanup](/ignite-element/handbook/ownership/).

## Share with agents and tests

Pass that same started source to `igniteCore`.

A headless test, a tool loop, and the registered views then share one actor.

```ts title="shared-counter-tools.ts"
import { defineToolSchema, igniteTools } from 'ignite-element/tools';
import { openai } from 'ignite-element/tools/openai';
import { core } from './shared-counter';

export const counterToolSchema = defineToolSchema({
  increment: {
    description: 'Increment the shared counter.',
    input: { type: 'object', properties: {} },
    gated: true,
  },
});

export const counterTools = igniteTools({
  core,
  schema: counterToolSchema,
  dialect: openai,
  canExecute: (name) =>
    name !== 'increment' || Boolean(core.get('states').canIncrement),
});
```

`canExecute` is the tools gate.

It reads the current projection from this shared core.

`run` acknowledges the command; `until` waits for later source work to settle.

`observe` remains for ongoing fan-in.

See [Build for agents](/ignite-element/guides/agent-runtime-v3/) and [Tools](/ignite-element/guides/tools/).

## Own the source lifetime

| Source input | Ownership |
| --- | --- |
| Existing XState actor | Application-owned; Ignite releases only its observation resources |
| XState machine definition | Existing Ignite acquisition creates private isolated actors and owns their release |
| Existing Redux store or MobX observable | Application-owned behavior, using `ignite-element/redux` or `ignite-element/mobx` and native operations |

The root `igniteCore()` is source-free and registrar-only.

Navigation removes observers, not the feature's source.

Source-native sign-in, sign-out and account reset can keep one core and its registrations.

When a feature or session permanently discards its core, dispose the core.

Stop a borrowed actor only if that owner also created the actor and nothing else needs it.

A feature module that owns the pair is in [Own a feature module](#own-a-feature-module).

This example shows the release order:

```ts
import { createActor, createMachine } from 'xstate';
import { igniteCore } from 'ignite-element/xstate';

const machine = createMachine({});
const source = createActor(machine).start();
const core = igniteCore({ source });
try {
  core.dispose();
} finally {
  source.stop();
}
```

The core releases its observations; the application stops its actor.

Repeated core disposal does not release resources again.

The application must release any observations it created separately.

## Own a feature module

A feature module owns its source and `igniteCore` pair.

Create the source, or borrow a shared started actor.

Pass that source into `igniteCore` with `states`, `commands`, `events`, and `effects`.

Register views with `home(tag, renderer)`. There is no `view:` on the core.

When the feature unmounts, the session ends, or a test tears down, dispose the core.

Then stop the actor only if this owner created the source and nothing else needs it.

A shared started actor keeps the house running. Dispose releases observation only.

The [ownership table](#own-the-source-lifetime) is that same rule: a started actor is application-owned; a machine definition creates isolated actors that Ignite releases.

This factory is the owned pair. Hand-written dispose is the teardown:

```tsx title="lights-feature.tsx"
import { assign, createActor, setup } from 'xstate';
import { igniteCore } from 'ignite-element/xstate';

const lightsMachine = setup({
  types: {
    context: {} as { living: boolean },
    events: {} as { type: 'TOGGLE'; on: boolean },
  },
}).createMachine({
  context: { living: false },
  on: {
    TOGGLE: {
      actions: assign({ living: ({ event }) => event.on }),
    },
  },
});

function createLightsFeature() {
  const actor = createActor(lightsMachine).start();
  const home = igniteCore({
    source: actor,
    states: (snapshot) => ({ living: snapshot.context.living }),
    commands: ({ source: actor }) => ({
      toggle: (on: boolean) => actor.send({ type: 'TOGGLE', on }),
    }),
  });
  home('ignite-lights', (ctx) => (
    <button onClick={() => ctx.toggle(!ctx.living)}>
      Living: {ctx.living ? 'On' : 'Off'}
    </button>
  ));
  return {
    core: home,
    dispose() {
      try {
        home.dispose();
      } finally {
        actor.stop();
      }
    },
  };
}

function createPanelFeature(
  sharedActor: ReturnType<typeof createActor<typeof lightsMachine>>,
) {
  const home = igniteCore({
    source: sharedActor,
    states: (snapshot) => ({ living: snapshot.context.living }),
    commands: ({ source: actor }) => ({
      toggle: (on: boolean) => actor.send({ type: 'TOGGLE', on }),
    }),
  });
  return {
    core: home,
    dispose() {
      home.dispose();
      // do not stop sharedActor
    },
  };
}
```

A panel that borrows the house uses `createPanelFeature`. Dispose releases observation only. Do not stop the shared actor.

Call `dispose()` from the feature's existing unmount, session-end, or test teardown.

The [Smart Home example](https://github.com/0xjcf/ignite-element/tree/beta/examples/agents/smart-home) `createLocalHomeSession` is this pair on the full house.

[Ownership & cleanup](/ignite-element/handbook/ownership/) is the lifetime reference.

[Shared sources](/ignite-element/explainers/shared-sources/) is the same house through one started actor.

## React and React Native

<Code code={reactCode} lang="tsx" title="React shared counter" />

Shared cores are ready after owner-controlled construction.

Unmounting a view releases its subscription, not the core.

Each core/source instance has one effect evaluator.

It starts on legitimate runtime use or a committed subscription or element connection.

It establishes a baseline, then queues delivery after source processing.

The activated shared evaluator remains active until core disposal, even with no connected views.

Delivery does not guarantee a renderer update or framework commit.

See [delivery and ownership](/ignite-element/handbook/events/#delivery-and-ownership) for the canonical activation, lifetime, disposal, synchronous-void and error rules.

## Source-owned account and receipt behavior

The synthetic preference source owns account identity and a generation.

Sign-out clears private state and exits its invocation; an old intent carries an old generation and is rejected.

A new account uses the same actor/core, not rebinding.

### Handle late confirmations

The receipt actor lives above `pending` and `unknown`.

A native XState deadline does not discard a later confirmation while that operation is live.

Account and generation checks reject mismatched receipts.

A transport error is unknown, not a confirmed rejection or permission to retry.

Ending local observation or exiting a source state does not undo backend work already accepted.
