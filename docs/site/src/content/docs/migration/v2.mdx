Ignite Element v2 introduces the default Ignite JSX renderer, diff-based JSX updates, and an optional `ignite.config.ts` compatibility layer for shared styles, diagnostics, or `lit`. Use this guide to upgrade from v1.x.

This page describes historical v2.2.2 behavior, not the current v3 beta.

If you are upgrading from v2 to v3, use [Migrate from v2 to v3](/ignite-element/migration/v3/).

## TL;DR

1. Upgrade dependencies: `pnpm add ignite-element@2.2.2`.
2. Set `"jsxImportSource": "ignite-element/jsx"` (or add the pragma per file).
3. Move component CSS into ordinary `<style>` tags or imported CSS text.
4. Add `ignite.config.ts` only if you need shared shadow-root styles, diagnostics, or `renderer: "lit"`.
5. Verify v2 shared-adapter teardown; `cleanup: false` retains observation across element disconnects.

## 1) Install

```bash
pnpm add ignite-element@2.2.2
# keep your peer: xstate | @reduxjs/toolkit | mobx
```

If you rely on lit templates, keep `lit-html` installed.

## 2) Configure JSX

```jsonc
// tsconfig.json
{
  "compilerOptions": {
    "jsx": "react-jsx",
    "jsxImportSource": "ignite-element/jsx"
  }
}
```

Or add a file-level pragma:

```ts
/** @jsxImportSource ignite-element/jsx */
```

## 3) Update styling defaults

For the default v2 path, keep styles next to the JSX that uses them:

This styling fragment assumes `component` is your v2 source-backed registrar with a `title` state.

```tsx title="v2 styling (fragment)"
const cardStyles = `
  :host { display: block; }
  .card { padding: 1rem; }
`;

component('my-card', ({ title }) => (
  <>
    <style>{cardStyles}</style>
    <section className="card">{title}</section>
  </>
));
```

If your bundler supports CSS-as-text imports, you can import that string instead of declaring it inline.

## 4) Add `ignite.config.ts` only for shared defaults

```ts
import { defineIgniteConfig } from 'ignite-element';

export default defineIgniteConfig({
  styles: new URL('./styles.css', import.meta.url).href,
  logging: 'warn',
  // renderer: 'lit',
});
```

Load the config before registering components. A v2 application can retain its existing config-loader plugin; v3 configuration changes are covered in the [v2-to-v3 guide](/ignite-element/migration/v3/#update-configuration-imports).

## 5) Update renderers

- **Ignite JSX (recommended)**: write JSX in your component render function.
- **lit**: set `renderer: "lit"` to keep lit templates. Renderer choice is per project, not per component.

## 6) Shared Adapter Teardown

In v2.2.2, shared adapters are reference-counted and release their observation after the last element disconnects by default. `cleanup: false` retains that observation. Borrowed actors remain application-owned.

The following fragment assumes your application supplies `machine`, the `states` projection and `Renderer`.

```ts
const actor = createActor(machine);
actor.start();

const shared = igniteCore({ source: actor, cleanup: false, states: /* ... */ });
shared('shared-counter', Renderer);
// later: actor.stop();
```

## 7) Checklist

- [ ] Dependencies updated to v2
- [ ] JSX runtime configured
- [ ] Component-local `<style>` tags or CSS-text imports in place for default styling
- [ ] `ignite.config.ts` added only if shared styles, diagnostics, or `lit` are needed
- [ ] Renderer choice confirmed (Ignite JSX or lit)
- [ ] Shared adapter teardown verified
