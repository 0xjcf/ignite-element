:::caution[v3 is in beta]
v3 publishes under the `beta` dist-tag. Install with `@beta`; the stable
`latest` tag is still v2.2.x. APIs are stable but may see small changes before
the `3.0.0` release.
:::

`3.0.0-beta.12` is published and verified, including the source-free constructor,
testing retirement, final disposal and neutral React bindings. Install this exact
version or `ignite-element@beta`; beta.11 does not include these changes.
All four `beta` tags and the three scoped packages' `latest` tags point to beta.12.
The facade `ignite-element@latest` remains `2.2.2`.

Ignite Element v3 keeps the default Ignite JSX renderer and headless runtime from v2, and adds a cleaner install surface, a states-first projection contract, and a narrower public API.

:::tip[Will this break my app?]
The states projection cutover is breaking for v3 beta consumers: config `view`
is removed, `states` receives the bare native snapshot, and headless projection
fields use states vocabulary. The renderer callback supplied during component
registration remains a view.
:::

## TL;DR

1. Install the beta: `pnpm add ignite-element@beta` (plus the one state library you use).
2. State libraries (`xstate`, `redux`, `@reduxjs/toolkit`, `mobx`) and `lit-html` are now **optional** peers — install only what you use.
3. Use the canonical states projection: `states: (snapshot) => …`; config `view` is rejected.
4. The removed `ignite-element/config/*` and `ignite-element/renderers/*` subpaths are no longer part of the public API.

## 1) Install the beta

```bash
pnpm add ignite-element@beta xstate
# pnpm add ignite-element@beta @reduxjs/toolkit   # Redux
# pnpm add ignite-element@beta mobx               # MobX
```

`ignite-element` now depends on the scoped packages `@ignite-element/core`, `@ignite-element/adapters`, and `@ignite-element/renderer`. They install automatically as dependencies — you don't add them yourself, and your imports stay `ignite-element` and `ignite-element/<adapter>`.

## 2) Optional peer dependencies

In v3 the state libraries and `lit-html` are declared as **optional** peer dependencies. Installing `ignite-element@beta xstate` no longer pulls in Redux, MobX, Redux Toolkit, or lit, and you won't see "unmet peer" warnings for the adapters you don't use. `lit-html` is only needed if you opt into the `lit` render strategy — the default Ignite JSX renderer requires no renderer dependency.

Selecting lit is now **config-free**: install `@ignite-element/renderer` and `lit-html` as direct dependencies, import `@ignite-element/renderer/lit`, and author lit-html templates — Ignite auto-detects them and renders with lit. You no longer set `renderer: 'lit'` in `ignite.config.ts` just to use lit (it remains the way to *force* one renderer project-wide). See [Rendering](/ignite-element/concepts/rendering/).

## 3) Canonical states projection

Replace the beta.10 `view` projection with `states`, passing the bare native snapshot:

```ts
// v2 / early v3 beta
view: ({ context, transport }) => ({
  status: context.status,
  connected: transport.state === "connected",
});

// v3
states: (snapshot) => ({
  status: snapshot.context.status,
  connected: snapshot.transport.state === "connected",
});
```

XState uses native `StateFrom<Machine>` snapshots. XState and Actor-Web state live under `snapshot.context`; Redux and MobX state are the snapshot itself. Also migrate `getView`/`watchView` to `get("states")`/`watch`, `schema.view` to `schema.states`, execution results to `{ snapshot, states, events }`, and public renderer access from raw `state`/`send` to derived states and semantic commands.

## 4) Narrower public API

v3 locks the stable public surface to the root entrypoint, the adapter entrypoints (`ignite-element/xstate`, `/redux`, `/mobx`, `/actor-web`), and the JSX entrypoints. The following are no longer public:

- The `ignite-element/config/*` and `ignite-element/renderers/*` subpaths.
- Root exports for config loaders, renderer-strategy registration, global style mutation, and factory internals.

If an advanced app still needs shared shadow styles or renderer diagnostics, import the underlying `@ignite-element/renderer` primitives directly in app-owned code. For the default Ignite JSX path you need none of this.

## Testing/story retirement in beta.12

Beta.12 removes `test` from all five public barrels, the 27 dedicated testing/story types, the declaration-reachable testing graph, `record(name)`, and the accessibility bridge. Migrate to ordinary runtime/source assertions and real registered-element DOM queries. Retained runtime results, typed commands/events, subscriptions, snapshots, derived states and schema remain. Portable receipts and internal lifecycle histories are intentionally removed; there is no alias or replacement recorder.

See the [migration table](/ignite-element/api/testing-dsl/) and [complete testing examples](/ignite-element/guides/testing/). Source/application ownership of asynchronous work, cancellation and native shutdown is unchanged. This major changeset was consumed into beta.12; publication is established separately by verified public package bytes and provenance.

## Core API and React bindings in beta.12

Source-backed owners use `get('states')`, `get('schema')`, `get('commands')`,
`get('events')`, `watch`, `on`, `execute`, and `dispose`. The former raw/derived
getters and watchers, schema getter and core `canExecute` query have no aliases.
Native source snapshot APIs and paired execution results remain. Component
handles expose discovery-only keyed reads; root source-free construction remains
registrar-only.

Commands are ordinary functions. Remove the helper and input builders, move
existing tool definitions to explicit application schemas, and project meaningful
availability into states. Unknown discovery schemas are null, not fabricated
validation. State/command name collisions now fail rather than overwrite.

Prepare a framework-owned core once with `core.get('states')` outside rendering.
Import `useIgnite` from `ignite-element/react`; move `igniteReact` and wrapper
types to `ignite-element/react/web`. Move Actor-Web factories requiring a real
element host to `ignite-element/actor-web/web`. The neutral source/factory path
never transfers native close authority. See [headless runtime](/ignite-element/api/headless-runtime/)
and [host integration](/ignite-element/guides/host-app-integration/) for lifetime,
single-input execution, immutable projection and native-test-host limits.

## Verify

For an existing plain TypeScript controller, use the
[shared-controller guide](/ignite-element/guides/plain-controllers/) rather than
rewriting its behavior into a state library. The checkout example uses built public
exports and exact packed candidates; registry beta.11 is not an equivalent input.
Keep session cores unregistered and move each login epoch to a new application owner.

- Reinstall and run a TypeScript check (`pnpm exec tsc --noEmit`).
- Confirm only your chosen state library is installed (`npm ls xstate redux mobx`).
- Smoke-test a component per [Your first component](/ignite-element/getting-started/first-component/).
