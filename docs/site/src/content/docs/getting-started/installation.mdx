:::caution[v3 is in beta]
v3 publishes under the `beta` dist-tag, so install with `@beta`. The stable
`latest` tag is still v2.2.x. See the [v2 → v3 migration guide](/ignite-element/migration/v3/)
for what changed.
:::

Pick your package manager and install Ignite Element with the one state adapter you use:

```bash
pnpm add ignite-element@beta xstate
# pnpm add ignite-element@beta @reduxjs/toolkit   # Redux
# pnpm add ignite-element@beta mobx               # MobX
```

The state libraries are optional peer dependencies, so only the one you install is pulled in — adding `ignite-element@beta` never drags in Redux/MobX/lit when you only use XState. `ignite-element` depends on the scoped `@ignite-element/core`, `@ignite-element/adapters`, and `@ignite-element/renderer` packages internally; they install automatically and you don't reference them directly.

## Compatibility

`ignite-element@3.0.0-beta.2` declares the versions below. The state libraries and `lit-html` are **optional** peers — install only the ones the adapter you import needs; npm/pnpm warn if an installed version is below the minimum.

| Dependency | Required | Needed for |
| --- | --- | --- |
| Node.js | `>=22` | running the build/dev toolchain |
| TypeScript | `5.x` (authored against 5.9) | the typed JSX authoring path |
| `xstate` | `>=5.19.0` | `ignite-element/xstate` |
| `@reduxjs/toolkit` | `>=2.3.0` | `ignite-element/redux` |
| `redux` | `>=5.0.1` | `ignite-element/redux` (peer of Redux Toolkit) |
| `mobx` | `>=6.13.5` | `ignite-element/mobx` |
| `lit-html` | `>=3.2.1` | the optional legacy `lit` renderer |

The version ranges come from each package's `peerDependencies`; TypeScript and Node reflect the toolchain the v3 types and packages are built and tested against. Because v3 is in beta, pin a known-good range in your own `package.json` until the stable `latest` release.

### 1) Configure JSX (required for the default Ignite JSX path)

Add the Ignite JSX runtime to your `tsconfig.json` (or use a file-level pragma):

```jsonc
{
  "compilerOptions": {
    "jsx": "react-jsx",
    "jsxImportSource": "ignite-element/jsx"
  }
}
```

### 2) Start building

For the default path, you do not need `ignite.config.ts`, a bundler plugin, or shared adapter teardown overrides. The default Ignite JSX renderer is registered automatically by the public entrypoints.

### Optional advanced and legacy setup

Use the advanced setup only when you need `@ignite-element/renderer` primitives for shared styles, diagnostics, or the legacy `lit` path.

- **Advanced config**: [defineIgniteConfig (@ignite-element/renderer)](/ignite-element/api/define-ignite-config/)
- **Legacy tooling notes**: [Tooling](/ignite-element/guides/tooling/)
- **Legacy renderer notes**: [Renderers](/ignite-element/api/renderers/)

### Runtime dependencies and tree shaking

Ignite Element stays lean but is not literally “zero dependency”: you must install the state library you choose (XState, Redux Toolkit, or MobX). Ignite JSX uses a minimal custom renderer (no framework runtime). If you opt into the lit renderer, install `lit-html`. Import from the adapter entry point that matches your state library (`ignite-element/xstate`, `ignite-element/redux`, or `ignite-element/mobx`) so only the renderer and adapter you pick are pulled into your bundle and unused adapters are tree-shaken.

### Verify your setup

- Run a TypeScript check (e.g., `pnpm exec tsc --noEmit` or `npx tsc --noEmit`) to ensure JSX settings work.
- Create a smoke test component via [Your first component](/ignite-element/getting-started/first-component/).
- Add config/plugins only if you need global renderer defaults, shared styles, or lit.
