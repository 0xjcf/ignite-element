:::caution[v3 is in beta]
v3 publishes under the `beta` dist-tag, so install with `@beta`. The consumer-facing
stable tag remains `ignite-element@latest = 2.2.2`. See the [v2 → v3 migration guide](/ignite-element/migration/v3/)
for what changed.
:::

Pick your package manager and install Ignite Element with the one state adapter you use:

```bash
pnpm add ignite-element@beta xstate
# pnpm add ignite-element@beta @reduxjs/toolkit   # Redux
# pnpm add ignite-element@beta mobx               # MobX
```

Ignite Element v3 and its scoped packages are native ESM-only. Use ESM `import` syntax; v3 does not advertise a CommonJS `main` or `require` contract.

The state libraries are optional peer dependencies, so only the one you install is pulled in — adding `ignite-element@beta` never drags in Redux/MobX/lit when you only use XState. `ignite-element` depends on the scoped `@ignite-element/core`, `@ignite-element/adapters`, and `@ignite-element/renderer` packages internally; normal facade consumers receive them automatically and do not import them directly.

Node 22+ and TypeScript 5.x are required. For the full version matrix (state libraries, `lit-html`), see [Compatibility](/ignite-element/api/compatibility/).

## 1) Configure JSX (required for the default Ignite JSX path)

Add the Ignite JSX runtime to your `tsconfig.json` (or use a file-level pragma):

```jsonc
{
  "compilerOptions": {
    "jsx": "react-jsx",
    "jsxImportSource": "ignite-element/jsx"
  }
}
```

## 2) Start building

For the default path, you do not need `ignite.config.ts`, a bundler plugin, or shared adapter teardown overrides. The default Ignite JSX renderer is registered automatically by the public entrypoints.

## Optional advanced and legacy setup

Use the advanced setup only when you need `@ignite-element/renderer` primitives for shared styles, renderer diagnostics, or the optional lit renderer. Direct scoped imports must be direct dependencies. For lit:

```bash
pnpm add ignite-element@beta @ignite-element/renderer@beta lit-html
```

Renderer selection remains config-free; importing `@ignite-element/renderer/lit` registers the strategy. See [Rendering](/ignite-element/concepts/rendering/).

- **Advanced config**: [`ignite.config.ts`, renderer selection, and bundler notes](/ignite-element/api/advanced-config/)

## Runtime dependencies and tree shaking

Ignite Element stays lean but is not literally “zero dependency”: you must install the state library you choose (XState, Redux Toolkit, or MobX). Ignite JSX uses a minimal custom renderer (no framework runtime). If you opt into the lit renderer, install `lit-html`. Import from the adapter entry point that matches your state library (`ignite-element/xstate`, `ignite-element/redux`, or `ignite-element/mobx`) so only the renderer and adapter you pick are pulled into your bundle and unused adapters are tree-shaken.

## Verify your setup

- Run a TypeScript check (e.g., `pnpm exec tsc --noEmit` or `npx tsc --noEmit`) to ensure JSX settings work.
- Create a smoke test component via [Your first component](/ignite-element/getting-started/first-component/).
- Add config/plugins only if you need global renderer defaults, shared styles, or diagnostics. Using lit needs no config, but the direct `@ignite-element/renderer/lit` import requires `@ignite-element/renderer` and `lit-html` to be declared dependencies.

## Project checklist

A baseline for a real project:

- **Node & package manager**: Node 22+. Pick pnpm, npm, or yarn and use it consistently.
- **TypeScript JSX**: set `"jsx": "react-jsx"` and `"jsxImportSource": "ignite-element/jsx"` (or the per-file pragma).
- **Testing**: add a runner (Vitest or Jest) and a smoke test per web component (mount + basic interaction). See [Test components](/ignite-element/guides/testing/).
- **Linting/formatting**: use your preferred stack (ESLint/Prettier, Biome, …); the package imposes none.
- **Advanced setup (optional)**: reach for [`ignite.config.ts`](/ignite-element/api/advanced-config/) only when you need project-wide renderer defaults, shared styles, or diagnostics. Lit is config-free — see [Rendering](/ignite-element/concepts/rendering/).
