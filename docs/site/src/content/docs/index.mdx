Ignite connects an existing state source to Web Components, React, or headless
consumers. Your source owns behavior; Ignite observes it and provides derived
values and commands to a view.

__source → source-native snapshot → states → view__

## Install v3 beta

This handbook describes __v3 (beta), published beta.14__. Install the beta package
and the source library you use:

```sh title="Terminal"
pnpm add ignite-element@beta xstate
```

To pin this release, use `ignite-element@3.0.0-beta.14` instead of `@beta`.
The stable facade policy is `ignite-element@latest = 2.2.2`;
[stable v2 documentation](/ignite-element/2.x/) is separate.
Use Node 22+ and a TypeScript/bundler project. v3 is native ESM-only.

## Build a component

Save this complete file as `src/toggle.tsx`. The file-level pragma selects Ignite
JSX; an application using only Ignite JSX can instead set `jsx: "react-jsx"`
and `jsxImportSource: "ignite-element/jsx"` in `tsconfig.json`.

<Code code={toggle} lang="tsx" title="src/toggle.tsx" />

Load it from your bundler's HTML entry:

```html title="index.html"
<!doctype html>
<html lang="en">
  <head><meta charset="UTF-8" /><title>Ignite toggle</title></head>
  <body>
    <ignite-toggle></ignite-toggle>
    <script type="module" src="/src/toggle.tsx"></script>
  </body>
</html>
```

For example, in a new directory containing those two files:

```sh title="Terminal"
pnpm add -D vite typescript
pnpm exec vite
```

The actor owns `off` and `on`. Inline `states` derives `isOn` from its native
snapshot; the inline command sends `TOGGLE`. The renderer receives inferred
values and commands through `ctx`. No configuration file or notifications are
needed for this component. Call `dispose()` at final application shutdown.

Ignite fits applications that already own a source and need several ways to
observe and control it. It does not supply routing, business persistence, or
server rendering. See [compatibility](/ignite-element/api/compatibility/).
