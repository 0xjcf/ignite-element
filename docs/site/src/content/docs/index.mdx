__source → states → view__

Connect your state source to Web Components, React, or headless consumers.
Your source owns state and behavior. `states` selects values for the view;
`commands` sends user actions to the source.

## Install v3 beta

This guide uses __v3 beta.14__. For `ignite-element@latest` (v2.2.2), see the
[stable v2 documentation](/ignite-element/2.x/).

This example renders a Web Component. Use your existing TypeScript/JSX web
project, or create one with the optional setup below.

<details>
<summary>Starting a new project? Set up Vite</summary>

In an empty directory, with Node 22.12+ and pnpm installed, run:

```sh title="Terminal"
pnpm init
pnpm add -D vite typescript
```

Vite builds and serves this example locally; Ignite does not require Vite.

</details>

Install Ignite and XState in your project:

```sh title="Terminal"
pnpm add ignite-element@3.0.0-beta.14 xstate
```

`toggleMachine` owns `off`, `on`, and the flip count. Ignite creates a private
actor for each `<ignite-light-switch>`, so each element has its own state.
`states` derives `isOn`, `label`, and `count`; the `toggle` command sends `FLIP`
to that element’s actor. The view displays those values through `ctx`.

Create `src/light-switch.css` alongside the TSX file. The stylesheet is loaded
inside the element’s shadow root, so its bulb and switch styles stay local.

<details>
<summary>Optional: configure JSX for the whole project</summary>

For a project using only Ignite JSX, use these compiler options instead of the
file-level pragma. v3 uses native ES modules.

```json title="tsconfig.json"
{
  "compilerOptions": {
    "target": "ES2022",
    "module": "ESNext",
    "moduleResolution": "Bundler",
    "jsx": "react-jsx",
    "jsxImportSource": "ignite-element/jsx",
    "strict": true,
    "noEmit": true
  },
  "include": ["src"]
}
```

</details>
