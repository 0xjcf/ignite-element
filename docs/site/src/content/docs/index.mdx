Ignite Element gives you a thin, typed layer around modern state systems so you can ship platform-native custom elements without dragging along an app framework runtime. Commands express intent, effects express consequences, and the same component contract can run in the DOM, in tests, or headlessly.

:::tip[Goal]

Fast onboarding: install, enable JSX once, and ship a component in minutes.

:::

:::note[Using v1?]

You’re reading the Ignite Element v2 docs. If you’re upgrading from v1, start with the [migration guide](/ignite-element/migration/v2/).

:::

## Quick install

```bash
pnpm add ignite-element@beta xstate
# or npm/yarn equivalents
```

:::caution[v3 is in beta]
Install with `@beta` — the stable `latest` tag is still v2.2.x. The state
libraries are optional peers, so only `xstate` is pulled in here. See the
[v2 → v3 migration guide](/ignite-element/migration/v3/).
:::

Add JSX runtime settings for Ignite JSX (the default renderer):

```jsonc
// tsconfig.json
{
  "compilerOptions": {
    "jsx": "react-jsx",
    "jsxImportSource": "ignite-element/jsx"
  }
}
```

No `ignite.config.ts`, renderer selection, config loader, or plugin wiring is required for the default v3 path. For most components, keep styles local to the render output with ordinary `<style>` tags. Reach for `ignite.config.ts` only when you need shared shadow-root styles, diagnostics, or the legacy `lit` renderer. If a host enforces strict `style-src` CSP rules, use emitted stylesheet URLs through shared styles instead of inline `<style>` tags.

## Create a simple machine-backed component

```tsx
import { igniteCore } from 'ignite-element/xstate';
import { createMachine } from 'xstate';

const styles = `
  button {
    border-radius: 999px;
    padding: 0.65rem 1rem;
    font-weight: 600;
  }
`;

const machine = createMachine({
  initial: 'off',
  states: {
    off: { on: { TOGGLE: 'on' } },
    on: { on: { TOGGLE: 'off' } },
  },
});

const component = igniteCore({
  source: machine,
  events: (event) => ({
    toggled: event<{ isOn: boolean }>(),
  }),
  view: ({ matches }) => ({
    isOn: matches('on'),
  }),
  commands: ({ actor }) => ({
    toggle: () => actor.send({ type: 'TOGGLE' }),
  }),
  effects: (_snapshot, _prevSnapshot, { emit, select }) => {
    const isOn = select((snapshot) => snapshot.matches('on'));
    if (!isOn.changed) return;
    emit('toggled', { isOn: isOn.current });
  },
});

component('my-toggle', ({ isOn, toggle }) => (
  <>
    <style>{styles}</style>
    <button onClick={toggle}>{isOn ? 'On' : 'Off'}</button>
  </>
));
```

Add the element anywhere:

```html
<my-toggle></my-toggle>
```

Want to go deeper with XState itself? See the <a href="https://stately.ai/docs" target="_blank" rel="noreferrer" aria-label="XState docs (opens in a new tab)">XState docs&nbsp;↗</a>.

## Why teams pick Ignite Element

- Platform-native distribution: ship one custom element contract to plain HTML, React, Vue, or other hosts.
- Typed commands, view projection, effects, events, and headless runtime hooks without a React/Solid runtime.
- Keep XState, Redux Toolkit, or MobX—bring your state model instead of adopting a new reactive system just to ship components.
- No config is required for the default Ignite JSX path.
- Co-locate CSS with JSX through ordinary `<style>{styles}</style>` output, or import CSS text when your bundler supports it.
- Built-in lifecycle handling for shared vs. isolated adapters.
- Optional project-level config exists for renderer defaults, global styles, and diagnostics when you need it.

## Ignite vs. other options

- **React / Vue / Solid**: Ignite is a distribution layer for stateful UI, not a full app framework. Keep your existing app shell and ship DOM-native components across host boundaries.
- **Lit / Stencil**: Ignite is renderer-agnostic with pluggable adapters; keep your state library instead of adopting a bespoke reactive model.
- **State-library lock-in**: Swap XState/Redux/MobX without rewriting renderers; shared lifecycle handling stays consistent.

## Performance snapshot

- Tiny runtime surface—Ignite JSX uses a minimal custom JSX renderer (no framework runtime).
- Works with tree shaking; keep only the adapters/renderers you use.
- Bundle size check: [Bundlephobia](https://bundlephobia.com/package/ignite-element) for the current npm release.
- Shared adapters are reference-counted to avoid duplicate subscriptions.
