# Create and approve the Ignite Alchemy Mock Studio foundation and MagicPath prototype

## Source
Created with `fas create-task` on 2026-07-21.

## Problem
Define Ignite Alchemy as the product identity for the executable Story Workbench, then create its behavior-complete Mock Studio foundation and an interactive MagicPath prototype. Derive prioritized reviewer stories, bounded narratives, source-of-truth ownership, the Story session controller lifecycle, existing-machine validation references, race and precedence cases, experience inventory, design-system coverage, and state-to-screen coverage before visual synthesis. Prototype the approved scientific-alchemy application direction in MagicPath with stable reviewable states, token-first styling, control dispositions, accessibility contracts, measured browser receipts, and explicit human approval. The mock is design evidence only and MagicPath React never becomes production architecture.

## Acceptance criteria
- The durable Mock Studio foundation records prioritized reviewer stories, bounded narrative branches, authority, machine and lifecycle dispositions, race precedence, narrative-to-machine traceability, experience inventory, design-system coverage, and state-to-screen coverage before layout work begins.
- The product identity is Ignite Alchemy with Story Workbench as its descriptive category; canonical Story, Intent, Behavior, Checkpoint, receipt, XState, command, view, and coverage vocabulary remains technically literal.
- An interactive MagicPath prototype covers idle selection, paused stepping, replaying Back, completion with receipt, assertion failure, unknown or candidate transition evidence, no-XState-lens operation, and uncovered-gap review.
- The design is token-first, desktop-primary at 1440 by 900 and 1280 by 800 with a resilient 1024 layout, keyboard and reduced-motion behavior, accessible names, non-color status cues, and measured browser receipts.
- MagicPath project, component, revision, generated name, dimensions, preview, inspection date, and handoff role are recorded; generated React is not copied into production.
- The first material MagicPath round pauses for explicit human approval and approval.md records the accepted direction, covered narratives and states, exceptions, and deferred behavior.
- Each explicit existing machine cites a current source-aligned validation receipt; the proposed Story session controller cites its complete transition contract and queued implementation/POC tasks.
- Local browser measurements prove overflow, pane behavior, focus order, target sizes, contrast, reduced motion, and every visually distinct required state separately from MagicPath preview evidence.
- The work is tracked in `.fas/TASKS.md`.
- The task has a clear implementation and verification plan before execution starts.
- The task is queued in `.fas/queue/tasks.json` for the runtime.

## Proposed solution
- First create the behavior foundation and readiness matrices under `.mock-studio/ignite-story-workbench`; do not open visual synthesis until every P0/P1 narrative, machine, surface, control, and critical design-system gap has a disposition.
- Create a dedicated Ignite Alchemy MagicPath component as an interactive desktop-first product prototype using the existing Voice Workbench token direction and scientific-alchemy presentation language.
- Preserve MagicPath provenance and approved source as design input, render the prototype in a real browser at the target viewports, score it, and stop after the first material round for explicit approval.

## Alternatives considered
- Rejected treating the existing wireframe or a static diagram as an approved product design.
- Rejected copying MagicPath React into Ignite production source, starting visual synthesis before behavior readiness, and using fantasy terminology in place of canonical APIs.
- Rejected placing the Workbench prototype inside an unrelated MagicPath project without explicit provenance; use a dedicated project when available or record the approved host project decision.
