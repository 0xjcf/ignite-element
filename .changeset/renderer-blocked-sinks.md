Stop applying `innerHTML`, `outerHTML`, and `srcdoc`. This is the `innerHTML` half of the planned content-prop deprecation, in this beta rather than the next major. `textContent` still renders and stays deprecated until that major release. Use JSX children for text, and hosts for trusted rich content.

`href`, `src`, `action`, `formaction`, and `xlink:href` accept only strings whose scheme passes the same executable-URL check projection documents already use. `codebase` uses that check in the renderer only. Projection documents do not treat `codebase` as a URI key. The attribute name is lowercased before that check, so `<object DATA>` and `<object Data>` use the same rule as `data`. `javascript:`, `vbscript:`, and HTML, SVG, or XHTML `data:` URLs are not applied. `script`, `iframe`, `frame`, `object`, `embed`, and `applet` also reject every other `data:` URL, including `data:text/javascript` and an empty `data:`. `codebase` on `object` and `applet` rejects `javascript:`, `vbscript:`, and every `data:` URL. `https:` and relative codebase values still apply. `data:image/*` still applies on `img` and `source`. Other values, including `https:`, `mailto:`, and relative URLs, are. Non-string URL values are not applied. A later blocked URL on a reflected native property, including `iframe` `src`, `object` `data`, and `embed` `src`, is cleared by removing the attribute. A boolean the DOM normalized, such as `checked={1}`, is reset to `false`. A coerced `value`, such as `value={1}`, is reset to `""`. Those resets do not assign `undefined`. Reflected native URL properties `src`, `href`, `action`, `formAction`, and object `data` are left to attribute removal, and are assigned `undefined` only when the live property still equals the previous value. A custom-element property with one of those names, and a custom-element `codebase`, is cleared even when its setter normalized the previous value. A dropped property is chosen only because it was set last render and is absent now. That choice does not compare the stored value with the previous prop. A custom element's own setter is assigned `undefined`, including when it stored `0`, `false`, `""`, or `NaN`. The setter treats `null` and `undefined` as empty before `Number`, `trim`, or `new URL`. Inherited properties, including `id`, `title`, and `tabIndex` on a custom element, use the native reset: booleans become `false`, strings become `""`, `scrollTop` and `scrollLeft` become `0`, `volume` and `playbackRate` become `1`, and `tabIndex` is cleared by removing the attribute so it stays `-1`. A file input `value` is skipped and is never assigned `undefined`. A setter that throws is caught. A property that is not writable and has no setter is skipped. `base` `href` is not applied.

String event-handler props are not applied in any case, including `ONCLICK`, `OnError`, and `xlink:onclick`. Function handlers still use `addEventListener` and do not create an attribute.

`animate`, `set`, and `animateMotion` keep a string `attributeName`. That name is lowercased, whitespace and ASCII controls are removed, and any Clark `{namespace}` or namespace prefix is removed. When it is `href`, `from`, `to`, `by`, and `values` are not applied. A non-string `attributeName` is not applied, and those four values are not applied either, so `to="javascript:..."` cannot remain on a bare `animate`. `meta` refresh keys are normalized before `setAttribute` the same way a SMIL name is: lowercase, ASCII space and controls removed, then the local part after the last `:` or `}`. The only matches are `http-equiv` and `httpEquiv`. A trailing space or NUL in the key is that name, so it does not throw. A non-string is not applied, and a string that is `refresh` after that same stripping is not applied, so an array, a boxed string, a NUL, or a `toString` object cannot navigate. An ordinary attribute such as `data-equiv` is not that key. `content-type`, `Content-Type`, and `default-style` still apply. `srcset` candidate lists and `poster` are not checked. The no-host consumer ceiling for the sink guard is 4,864 B gzip, with no extra slack. This correctness split is over that sink ceiling on purpose. Its measured no-host consumer is 4,885 B gzip, with no extra slack.

A JSX strategy `detach()` drops a shadow root that was queued before the style injector loaded, and it drops a pending root so reconnecting that host does not style it. `flushPendingStyles()` does not write into a root while that root is disconnected. A root that was connected when it was queued, then disconnected during a move, stays pending and is styled when it reconnects. An Ignite element replays that parked root from `connectedCallback`, including when the host is appended into an already-connected parent shadow root. A shadow root whose host is not an Ignite element is replayed by a later JSX strategy `attach`. The document observer remains only as the fallback for those non-Ignite roots in light DOM. The same reconnect applies when the style injector itself loads during the move. A root that is removed, flushed, reinserted, and flushed again in the same task is styled once, and the reconnect observer disconnects when that last parked root is released. `detach()` also drops that root from the installed injector's `pendingRoots` and `parkedRoots`, including when `WeakRef` is missing, so the strong fallback is released. Roots that have not been connected yet still flush.

Development builds warn that `innerHTML`, `outerHTML`, and `srcdoc` are ignored and not applied. `textContent` still renders, and development builds still warn that it is deprecated until the next major release. A host `mount` may still assign `innerHTML`; that imperative callback is the escape hatch for trusted markup. Development builds also still log JSX replace fallbacks. Production and default builds omit those warnings and the fallback diagnostics, and they do not reference `process`.
