Stop applying `innerHTML`, `outerHTML`, and `srcdoc`. This is the `innerHTML` half of the planned content-prop deprecation, in this beta rather than the next major. `textContent` still renders and stays deprecated until that major release. Use JSX children for text, and hosts for trusted rich content.

`href`, `src`, `action`, `formaction`, and `xlink:href` accept only strings whose scheme passes the same executable-URL check projection documents already use. `codebase` uses that check in the renderer only. Projection documents do not treat `codebase` as a URI key. The attribute name is lowercased before that check, so `<object DATA>` and `<object Data>` use the same rule as `data`. `javascript:`, `vbscript:`, and HTML, SVG, or XHTML `data:` URLs are not applied. `script`, `iframe`, `frame`, `object`, `embed`, and `applet` also reject every other `data:` URL, including `data:text/javascript` and an empty `data:`. `codebase` on `object` and `applet` rejects `javascript:`, `vbscript:`, and every `data:` URL. `https:` and relative codebase values still apply. `data:image/*` still applies on `img` and `source`. Other values, including `https:`, `mailto:`, and relative URLs, are. Non-string URL values are not applied. A later blocked URL on a reflected native property, including `iframe` `src`, `object` `data`, and `embed` `src`, is cleared by removing the attribute. A boolean the DOM normalized, such as `checked={1}`, is reset to `false`. A coerced `value`, such as `value={1}`, is reset to `""`. Those resets do not assign `undefined`. Reflected native URL properties `src`, `href`, `action`, `formAction`, and object `data` are left to attribute removal, and are assigned `undefined` only when the live property still equals the previous value. A custom-element property with one of those names is cleared even when its setter normalized the previous value. `base` `href` is not applied.

String event-handler props are not applied in any case, including `ONCLICK`, `OnError`, and `xlink:onclick`. Function handlers still use `addEventListener` and do not create an attribute.

`animate`, `set`, and `animateMotion` keep a string `attributeName`. That name is lowercased, whitespace and ASCII controls are removed, and any Clark `{namespace}` or namespace prefix is removed. When it is `href`, `from`, `to`, `by`, and `values` are not applied. A non-string `attributeName` is not applied. `meta` `http-equiv` and `httpEquiv` must be primitive strings. A non-string is not applied, and a string that is `refresh` after that same stripping is not applied, so an array, a boxed string, a NUL, or a `toString` object cannot navigate. `srcset` candidate lists and `poster` are not checked. The no-host consumer ceiling is 4,818 B gzip after this guard, with no extra slack.

A JSX strategy `detach()` drops a shadow root that was queued before the style injector loaded, and it drops a pending root so reconnecting that host does not style it. `flushPendingStyles()` does not write into a root while that root is disconnected. A root that was connected when it was queued, then disconnected during a move, stays pending and is styled when it reconnects, including when it is reinserted inside another shadow root. The same reconnect applies when the style injector itself loads during the move. A root that is removed, flushed, reinserted, and flushed again in the same task is styled once, and the reconnect observer disconnects when that last parked root is released. `detach()` also drops that root from the installed injector's `pendingRoots` and `parkedRoots`, including when `WeakRef` is missing, so the strong fallback is released. Roots that have not been connected yet still flush.

Development builds warn that `innerHTML`, `outerHTML`, and `srcdoc` are ignored and not applied. `textContent` still renders, and development builds still warn that it is deprecated until the next major release. A host `mount` may still assign `innerHTML`; that imperative callback is the escape hatch for trusted markup. Development builds also still log JSX replace fallbacks. Production and default builds omit those warnings and the fallback diagnostics, and they do not reference `process`.
