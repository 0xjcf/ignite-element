BREAKING (beta): passed `checked`, `value`, and `selected` are applied on every render, including an explicit `false`. `defaultChecked`, `defaultValue`, and `defaultSelected` run before those live props. While `isComposing` is true, `value` is not written, so an `onInput` re-render does not reset the composition. The next render after composition ends writes that `value`. Dropping `checked`, `value`, or `selected` leaves the live form state as it was. Development builds warn, for example `` `checked` dropped on a controlled input; pass it every render or use a catalog form component ``. The catalog will own form state through cores later. A file input `value` is never assigned `undefined`.

JSX `innerText`, `textContent`, `outerText`, `innerHTML`, and `outerHTML` are unsupported on intrinsic elements. That is a TypeScript error. Development builds warn that each of those props is ignored and not applied, and production builds omit the warning. The props are never set and never reset. Children stay owned by the diff. They are unsupported in this beta, not deprecated until a later major. Use JSX children for text. A host `mount` may still assign `innerHTML` for trusted markup. `srcdoc` stays ignored and is not applied.

`href`, `src`, `action`, `formaction`, and `xlink:href` accept only strings whose scheme passes the same executable-URL check projection documents already use. `codebase` uses that check in the renderer only. Projection documents do not treat `codebase` as a URI key. The attribute name is lowercased before that check, so `<object DATA>` and `<object Data>` use the same rule as `data`. `javascript:`, `vbscript:`, and HTML, SVG, or XHTML `data:` URLs are not applied. `script`, `iframe`, `frame`, `object`, `embed`, and `applet` also reject every other `data:` URL, including `data:text/javascript` and an empty `data:`. `codebase` on `object` and `applet` rejects `javascript:`, `vbscript:`, and every `data:` URL. `https:` and relative codebase values still apply. `data:image/*` still applies on `img` and `source`. Other values, including `https:`, `mailto:`, and relative URLs, are. Non-string URL values are not applied. A later blocked URL on a reflected native property, including `iframe` `src`, `object` `data`, and `embed` `src`, is cleared by removing the attribute. A boolean the DOM normalized, other than `checked` and `selected`, is reset to `false` and is not assigned `undefined`. Dropping `checked`, `value`, or `selected` does not assign `false`, `""`, or `undefined`. Reflected native URL properties `src`, `href`, `action`, `formAction`, and object `data` are cleared by removing the attribute. They are not assigned `undefined`. A custom-element property with one of those names, and a custom-element `codebase`, is cleared even when its setter normalized the previous value. A dropped property is chosen only because it was set last render and is absent now. That choice does not compare the stored value with the previous prop. A custom element's own setter is assigned `undefined`, including when it stored `0`, `false`, `""`, or `NaN`, and including when that setter overrides an inherited name such as `id`. The setter treats `null` and `undefined` as empty before `Number`, `trim`, or `new URL`. On drop, leave `value`, `checked`, and `selected` untouched, reset `scrollTop` and `scrollLeft` to `0`, boolean props to `false`, and reflected attributes by `removeAttribute`. Two spellings of one prop on the same element are an authoring error: TypeScript rejects `acceptCharset` with `accept-charset`, `htmlFor` with `for`, `onClick` with `onclick`, `ariaLabel` with `aria-label`, and `className` with `class` where it can see both keys. Development builds warn otherwise. Production behavior for those attribute spellings is unspecified. URL and `on*` guards still apply to every spelling. Dropping `defaultValue`, `defaultChecked`, or `defaultSelected` on a native element leaves that default as it was. `defaultChecked={false}` and `defaultSelected={false}` are sets. A native attribute or event key that is still present under another casing is not a drop. If the previous render set both spellings of one event and the next keeps one, the other listener is unbound. `htmlFor`, `HtmlFor`, `acceptCharset`, `AcceptCharset`, `className`, and `httpEquiv` remove `for`, `accept-charset`, `class`, and `http-equiv`. An ARIA IDL name such as `ariaLabel` removes `aria-label`. Every other native prop, including those defaults, `volume`, `playbackRate`, and `currentTime`, is left alone and no attribute is written. A custom element's own setter is called with `undefined`, including a setter named `defaultValue`, `defaultChecked`, or `defaultSelected`. Own custom setters stay case-sensitive, so `foo` and `FOO` are different keys. Sets apply before drops. The content-prop ban covers intrinsic elements only. `length`, `options`, and `selectedOptions` are never set or reset. A file input `value` is skipped and is never assigned `undefined`. A setter that throws is caught. A property that is not writable and has no setter is skipped. `base` `href` is not applied.

String event-handler props are not applied in any case, including `ONCLICK`, `OnError`, and `xlink:onclick`. Function handlers still use `addEventListener` and do not create an attribute.

`animate`, `set`, and `animateMotion` keep a string `attributeName`. That name is lowercased, whitespace and ASCII controls are removed, and any Clark `{namespace}` or namespace prefix is removed. When it is `href`, `from`, `to`, `by`, and `values` are not applied. A non-string `attributeName` is not applied, and those four values are not applied either, so `to="javascript:..."` cannot remain on a bare `animate`. `meta` refresh keys are normalized before `setAttribute` the same way a SMIL name is: lowercase, ASCII space and controls removed, then the local part after the last `:` or `}`. The only matches are `http-equiv` and `httpEquiv`. A trailing space or NUL in the key is that name, so it does not throw. A non-string is not applied, and a string that is `refresh` after that same stripping is not applied, so an array, a boxed string, a NUL, or a `toString` object cannot navigate. An ordinary attribute such as `data-equiv` is not that key. `content-type`, `Content-Type`, and `default-style` still apply. `srcset` candidate lists and `poster` are not checked. There is no cached built-in element. Own custom setters are found by a walk that stops before `HTMLElement`, so a setter overriding an inherited name such as `id` gets `undefined`. Reflected props use `removeAttribute`, and a loaded image `width` does not become `0`. The no-host ceiling is 5,583 B gzip, raised from 5,447 B. The source-bundle gate is 4,130 B gzip, raised from 3,968 B. A file input `value` is still never assigned `undefined`.

A JSX strategy `detach()` drops a shadow root that was queued before the style injector loaded, and it drops a pending root so reconnecting that host does not style it. `flushPendingStyles()` does not write into a root while that root is disconnected. A root that was connected when it was queued, then disconnected during a move, stays pending and is styled when it reconnects. An Ignite element replays that parked root from `connectedCallback`, including when the host is appended into an already-connected parent shadow root. A shadow root whose host is not an Ignite element is replayed by a later JSX strategy `attach`. The document observer remains only as the fallback for those non-Ignite roots in light DOM. The same reconnect applies when the style injector itself loads during the move. A root that is removed, flushed, reinserted, and flushed again in the same task is styled once, and the reconnect observer disconnects when that last parked root is released. `detach()` also drops that root from the installed injector's `pendingRoots` and `parkedRoots`, including when `WeakRef` is missing, so the strong fallback is released. Roots that have not been connected yet still flush.

Development builds warn that `innerHTML`, `outerHTML`, `innerText`, `outerText`, `textContent`, and `srcdoc` are ignored and not applied. Those five content props are unsupported JSX props in this beta, not deprecated until a later major. They are never set or reset, and children stay owned by the diff. A host `mount` may still assign `innerHTML`; that imperative callback is the escape hatch for trusted markup. Development builds also still log JSX replace fallbacks. Production and default builds omit those warnings and the fallback diagnostics, and they do not reference `process`.
